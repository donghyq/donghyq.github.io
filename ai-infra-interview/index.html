01　性能测量与诊断

性能排查从一次请求的时间线开始：先确定用户感受到的延迟，再找 GPU 的空闲和热点，最后定位到具体 Kernel。

1.1 延迟、吞吐与 MFU

一次推理请求从排队开始，经过 Prefill、首 Token 和连续 Decode。先按时间段拆开用户延迟，再看吞吐、Goodput 和 MFU 各自在衡量什么。

MFU = Fmodel / (Δt × GPU 数量 × 单卡匹配精度的峰值 FLOP/s)

MFU（模型浮点计算利用率）统计有效模型计算；HFU（硬件浮点利用率）可包含激活重算等额外计算。分母选相同精度和稠密/稀疏口径，MoE 按实际激活的专家估算。Decode 还要结合带宽与延迟判断效率。

记录项固定或报告什么
负载模型/权重版本、输入与输出长度分布、并发或到达率、采样参数
资源GPU 型号与数量、精度、并行组、功耗/频率、软件版本
统计预热后测量、多轮重复；报告中位数与尾部、成功率及质量
缓存冷启动、热缓存、按 Token 统计的有效免算比例分别记录

1.2 四类瓶颈与第一轮判断

GPU 忙不过来和 GPU 没活干，可能表现为相同的低利用率。先观察时间线，再按计算、带宽、依赖延迟和系统调度四类原因逐项排查。

瓶颈常见证据优先检查
计算受限某计算管线吞吐接近可持续上限矩阵精度、指令数量、Tile（分块）形状和流水
带宽受限HBM（高带宽显存）、L2 或共享内存中某一级搬运繁忙字节数、合并访存、数据复用、融合和量化

系统受限CPU/GPU 空隙、排队、通信等待或慢节点提交、同步、通信组、调度和负载均衡

Roofline（屋顶线模型）给出计算与带宽的性能上界；依赖等待、启动开销和通信会让实际性能落在上界以下。优化后重新看时间线，热点可能已经改变。

from torch.profiler import profile, ProfilerActivity, record_function
x = torch.randn(2048,2048,device="cuda",dtype=torch.float16)
w = torch.randn(2048,2048,device="cuda",dtype=torch.float16)
for _ in range(10): y = x @ w  # warmup
torch.cuda.synchronize()        # 预热工作完成后才开始采集
with profile(activities=[ProfilerActivity.CPU,ProfilerActivity.CUDA],

    with record_function("gemm"):
        for _ in range(10): y = x @ w
    torch.cuda.synchronize()
print(p.key_averages().table(sort_by="self_cuda_time_total",row_limit=10))
p.export_chrome_trace("trace.json")

1.4 Roofline 与 GEMM 批量估算

一个矩阵乘要读多少数据、做多少 FLOPs，决定它可能先撞上算力还是带宽上限。Roofline 把两者放在同一模型中，给出优化方向。

AI = FLOPs / Bytes　　Performance ≤ min(P, BW × AI)　　交叉点 R = P / BW

对于 A[M,K] × W[K,N]，按权重读取一次、输入读取一次、输出写入一次估算，权重每元素 bw 字节，输入与输出每元素 ba 字节：

F ≈ 2MKN
Bytes ≈ KNbw + M(K+N)ba
Mcross ≈ RKNbw / [2KN − R(K+N)ba]

算例：K=7168、N=2048、bw=ba=2、R=200 FLOPs/Byte，交叉 M 约为 229。分母为正时才有这个交叉点。它帮助选择 Batch 扫描范围；最终配置再结合 Tile 对齐、缓存、尾延迟与显存测量。完整计算路径见 3.1 GEMM 分块。

1.6 变长 Batch 的 FLOPs、吞吐与 MFU

先固定计量对象。GEMM A[M,K] × B[K,N] 的主要计算量约为 2MNK FLOPs。变长序列要按有效 Token 统计；Padding 部分是否执行了实际 Kernel 计算，需要单独记账。

Dense Linear: FLOPs ≈ 2 × (Σᵢ Lᵢ) × K × N

以因果 Self-Attention 为例，忽略 Softmax、投影与常数开销，QKᵀ 和 PV 的矩阵乘合计约 4 × Σᵢ Lᵢ² × H FLOPs（按完整方阵计算的近似）。利用因果三角结构跳过无效位置时，实际执行 FLOPs 会减少；滑窗 Attention 则由窗口覆盖范围决定。

面试速记：记录 Token 分布、Padding 比例、Prefill/Decode 比例、激活 Expert 数、精度和 GPU 数；同时报告 Token/s、TTFT、TPOT、MFU 与 Kernel 吞吐。

02　CPU/GPU 执行与存储层次

GPU 为什么需要这么多线程？因为访存和指令都有等待时间。先理解线程如何调度，再看数据存在哪一层、怎么访问。

Grid、Block、Warp 与 SM延迟隐藏与 OccupancyCPU 缓存与 GPU 两条数据路径容量、延迟与带宽数量级合并访存、Bank Conflict 与地址重排GPU 地址空间与进程共享

2.1 Grid、Block、Warp 与 SM

CUDA 把线程组织成 Grid、Block 和 Warp，SM 再调度这些工作。先分清线程的逻辑层级与硬件执行层级，后面的 Occupancy 才有意义。

SIMT（单指令多线程）让程序按线程编写标量逻辑，硬件组织线程协作执行。Warp 中的分支用活跃掩码控制，各路径占用执行时间；让同一 Warp 的线程走相同路径通常更高效。共享数据的可见性仍通过同步原语建立。

linear_tid = threadIdx.x + blockDim.x × (threadIdx.y + blockDim.y × threadIdx.z)
warp_id = linear_tid / 32　　lane_id = linear_tid % 32

接着看：延迟隐藏与 Occupancy

2.2 延迟隐藏与 Occupancy

一次 HBM 读取可能等待数百周期。GPU 通过切换到其他就绪 Warp 隐藏等待，因此需要同时关注驻留 Warp 和真正可发射的 Warp。

概念读指标时的含义
Resident Warp（驻留线程束）状态和资源已分配在 SM 上
Eligible Warp（可发射线程束）依赖满足、当前可被调度
Issued Warp（已发射线程束）本周期实际提交了指令
Occupancy（占用率）活跃 Warp 数相对硬件上限的比例

每个 Block 的寄存器、SMEM 和线程数量共同约束驻留数量。算例：SM 有 65,536 个 32-bit 寄存器，Block 为 256 线程；每线程 64 个寄存器耗用 16,384 个，按该预算可放 4 个 Block；每线程 128 个时变为 2 个。实际还受分配粒度和其他资源约束。

2.3 CPU 缓存与 GPU 两条数据路径

CPU 和 GPU 都依赖片上存储减少远端读取。CPU 主要由硬件 Cache 自动管理；GPU 还提供程序显式管理的 Shared Memory。

2.5 合并访存、Bank Conflict 与地址重排

访问地址的排列直接决定内存事务数。先用 Warp 中每个线程的地址判断合并访存，再计算 Shared Memory 的 Bank 映射。

32-bit 标量读取：bank = (byte_address / 4) mod 32
shared[tid × stride]：不同 word、完整 Warp 时，冲突度 = gcd(stride,32)

按列读 tile[32][32] 时行跨度为 32 个 float，地址落在同一 bank。改为 tile[32][33] 后，bank 随行号移动。Padding（填充）改变跨度；Swizzle（布局重排）改变逻辑坐标到物理地址的映射。一个 32×32 float 教学布局可用 physical_col = col ^ row，按行和按列访问都能分散到 32 个 bank。

C++：按不同 word 统计 Bank 冲突，处理同地址广播
#include <algorithm>
#include <array>
#include <cstdint>
#include <stdexcept>
#include <unordered_set>
#include <vector>

// One warp; aligned scalar 32-bit READS only.
// Multiple lanes reading the same word are a broadcast.
int bank_degree(const std::vector<std::uint64_t>& byte_addresses) {
    if (byte_addresses.size() > 32) throw std::invalid_argument("at most 32 lanes");
    std::array<std::unordered_set<std::uint64_t>, 32> words;
    for (auto addr : byte_addresses) {
        if (addr % 4 != 0) throw std::invalid_argument("unaligned");
        auto word = addr / 4;
        words[word % 32].insert(word);
    }
    int waves = 0;
    for (const auto& bank : words)
        waves = std::max(waves, static_cast<int>(bank.size()));
    return waves;  // 0=no active lanes; 1=conflict free
}

3.1 GEMM：一次矩阵乘为什么要分块？

先看 C=A×B。C 的一个元素，是 A 的一行与 B 的一列做点积。计算相邻的多个 C 元素时，会反复使用同一行 A 或同一列 B。如果每个线程都从 HBM 重新读取这些元素，数据搬运就会限制计算速度。

解决办法是先选定一块输出 C[BM,BN]，然后沿 K 维逐段取 A[BM,BK] 和 B[BK,BN]。每一轮把这两个块加载到 Shared Memory（共享内存），在片上完成多个乘加，结果累积到同一块 C。走完整个 K，输出块才计算完成。

看下面的图时，先找到 C 的固定输出位置，再沿 K 方向观察 A/B 分块如何移动。

层级工作与复用
Block Tile一个线程块负责 B_M×B_N 的输出；合作加载 B_M×B_K 与 B_K×B_N 输入
Warp Tile线程束协作完成子块，适配矩阵指令与共享内存布局
Thread/Register Tile线程持有局部操作数和累加值，提高寄存器内复用
每个 K 阶段：C_tile += A[m:m+B_M, k:k+B_K] × B[k:k+B_K, n:n+B_N]

为什么还需要 Register Blocking（寄存器分块）？ Shared Memory 让同一个线程块复用数据；寄存器分块让每个线程或 Warp 复用已经取出的元素。接着才是 Tensor Core MMA 和 Double Buffer：前者提高矩阵计算吞吐，后者让下一块搬运与当前块计算重叠。

面试速记：BM×BN 决定输出 Tile，BK 决定 K 维每轮推进量。Tile 越大，数据复用通常越多，但寄存器和 SMEM 占用也增加。调优要同时看 Arithmetic Intensity（算术强度）、Occupancy（驻留线程束比例）和实际 Kernel 时间。

import torch

def _work_dtype(x):
    return torch.float64 if x.dtype == torch.float64 else torch.float32

def tiled_gemm(a,b,bm=3,bn=4,bk=2):
    """CPU 分块矩阵乘参考，用于形状与数值对照。"""
    if a.ndim!=2 or b.ndim!=2 or a.shape[1]!=b.shape[0]:
        raise ValueError("Invalid GEMM dimensions")
    if min(bm,bn,bk)<=0: raise ValueError("Positive tiles required")
    dtype=_work_dtype(a); a,b=a.to(dtype),b.to(dtype)
    m,k=a.shape; n=b.shape[1]
    out=torch.zeros((m,n),dtype=dtype,device=a.device)
    for i in range(0,m,bm):
        for j in range(0,n,bn):
            for t in range(0,k,bk):
                out[i:i+bm,j:j+bn] += a[i:i+bm,t:t+bk] @ b[t:t+bk,j:j+bn]
    return out

3.2 算术强度、Tile 大小与资源预算

分块让一份 A 元素服务多个输出列、一份 B 元素服务多个输出行。计算量和搬运量的比值随 Tile 变化，同时也消耗更多片上资源。

输入 SMEM/阶段 = (B_M×B_K + B_K×B_N) × 元素字节数
多阶段 SMEM ≈ stages × 输入/阶段 + scale/屏障/临时区

算例：BF16 下，B_M=B_N=128、B_K=32，一阶段为 16 KiB，双缓冲为 32 KiB；B_K 增为 128 后双缓冲为 128 KiB。更大的 Tile 减少部分重复读取，同时占用更多寄存器与 SMEM。调参同时记录执行时间、驻留 Block、spill 和 Tensor Core 活跃度。

向量化访存通过一次指令处理多个元素，减少地址和发射开销，前提是对齐与边界正确。Tile Scheduling（分块调度）让邻近任务复用 L2 中的 A/B；处理边界不整除时用掩码或填充。

3.4 Warp、Block 与 Two-pass Reduction

多个线程计算一个结果，必须决定谁负责合并。Warp、Block 和跨 CTA 的归约方式逐层扩大，浮点顺序也随之变化。

CUDA C++：两阶段行归约；代码覆盖 BLOCK=256、每段512、分段数≤256
// 前提：BLOCK=256；chunk_size=512；G=ceil(N/chunk_size) <= 256。
// 第一个 Kernel：每个 (row, part) 独立求一个部分和。
__global__ void row_partial(const float* x, float* tmp,
                            int N, int G, int chunk_size) {
    int row = blockIdx.y, part = blockIdx.x;
    int tid = threadIdx.x;
    __shared__ float buf[256];
    float v = 0.f;
    int end = min(N, (part + 1) * chunk_size);
    for (int c = part * chunk_size + tid; c < end; c += 256)
        v += x[row * N + c];
    buf[tid] = v;
    __syncthreads();
    for (int d = 128; d > 0; d >>= 1) {
        if (tid < d) buf[tid] += buf[tid + d];
        __syncthreads();
    }
    if (tid == 0) tmp[row * G + part] = buf[0];
}

// 第二个 Kernel：每行一个 CTA，归并该行的 G 个部分和。
__global__ void row_finish(const float* tmp, float* y, int G) {
    int row = blockIdx.x, tid = threadIdx.x;
    __shared__ float buf[256];
    buf[tid] = tid < G ? tmp[row * G + tid] : 0.f;
    __syncthreads();
    for (int d = 128; d > 0; d >>= 1) {
        if (tid < d) buf[tid] += buf[tid + d];
        __syncthreads();
    }
    if (tid == 0) y[row] = buf[0];
}

// G=(N+511)/512；先 launch row_partial(grid=(G,M), block=256)，
// 再 launch row_finish(grid=M, block=256)，二者在同一 CUDA stream。
// 如果 G>256，需要增加中间归约层，不能直接用此第二步。

两阶段增加了中间缓冲和一次启动，换来更大的行内并行度与明确的归约顺序。小 N 可由一个 CTA 完成；更大 N 可递归增加层级。AtomicAdd（原子加）提供单次更新原子性，其到达次序会影响浮点舍入。

import math
import torch

def _work_dtype(x):
    return torch.float64 if x.dtype == torch.float64 else torch.float32

def safe_softmax(x: torch.Tensor, dim: int = -1) -> torch.Tensor:
    """Finite logits / -inf masks. Fully masked row returns zero by convention."""
    if not x.is_floating_point() or x.shape[dim] == 0:
        raise ValueError("Nonempty floating-point logits required")
    if torch.isnan(x).any() or torch.isposinf(x).any():
        raise ValueError("NaN / +inf logits are not supported")
    z = x.to(_work_dtype(x))
    m = z.amax(dim=dim, keepdim=True)
    anchor = torch.where(torch.isfinite(m), m, torch.zeros_like(m))
    e = torch.exp(z - anchor)
    den = e.sum(dim=dim, keepdim=True)
    p = e / den.clamp_min(torch.finfo(z.dtype).tiny)
    return p.to(x.dtype)

def causal_mha(q: torch.Tensor, k: torch.Tensor, v: torch.Tensor,
               *, query_start: int | None = None) -> torch.Tensor:
    """q:[B,H,Tq,D], k:[B,H,Tk,D], v:[B,H,Tk,Dv].
    Keys are positions 0..Tk-1. By default q is the suffix of the cache.
    No padding, sliding window, GQA, dropout or production cache manager.
    """
    if q.ndim != 4 or k.ndim != 4 or v.ndim != 4:
        raise ValueError("Expected rank-4 tensors")
    if q.shape[:2] != k.shape[:2] or k.shape[:3] != v.shape[:3]:
        raise ValueError("Batch/head/sequence dimensions do not match")
    if q.shape[-1] != k.shape[-1] or q.device != k.device or k.device != v.device:
        raise ValueError("Q/K dimension or devices do not match")
    tq, tk = q.shape[-2], k.shape[-2]
    start = tk - tq if query_start is None else query_start
    if tq == 0 or tk == 0 or start < 0 or start + tq > tk:
        raise ValueError("Queries must lie within the cached key positions")
    allow = torch.arange(tk, device=q.device)[None, :] <= (
        start + torch.arange(tq, device=q.device)[:, None])
    dtype = _work_dtype(q)
    score = q.to(dtype) @ k.to(dtype).transpose(-1, -2)
    score = (score / math.sqrt(q.shape[-1])).masked_fill(~allow, -torch.inf)
    return (safe_softmax(score) @ v.to(dtype)).to(q.dtype)

5.2 MHA、MQA 与 GQA

MHA、MQA 和 GQA 的关键差异是 Query Head 与 KV Head 的共享关系。共享更多 KV Head 可以减少每 Token 的缓存和读取字节。

KV_bytes = 2 × layers × tokens × KV_heads × head_dim × bytes/element

算例：32 层、8 个 KV 头、维度 128、128K Token、BF16，每请求 KV payload 为 16 GiB。并行分片后每 rank 的大小取决于 KV 头是否分片或复制，另需计入页内空余、Scale 和通信缓冲。

Decode 的算术强度推导

B 个互不共享历史的请求，各有一个 Q，历史长度 T，Q/KV 头数为 Hq/Hkv、头维度 D、元素大小 b；忽略投影、Softmax 和缓存命中：

Attention FLOPs ≈ 4BHqTD
KV Bytes ≈ 2BHkvTDb
AI ≈ 2Hq / (Hkv b)

这个式子假设内核在多个 Q 头之间复用共享 KV。MLA 的潜变量计算使用不同维度，另按实际路径估算。

5.3 MLA：压缩 KV 后，Attention 怎么计算？

普通 MHA/GQA 会为历史 Token 保存 K/V。序列变长后，Decode 每步需要读取的历史数据也不断增长。MLA（Multi-head Latent Attention，多头潜在注意力）让多个 Head 共享一份较低维的潜变量 c_kv，降低缓存容量。

先看缓存写入：当前 Hidden State 经 Down Projection（下投影）得到 c_kv；RoPE（旋转位置编码）的 Key 位置分量单独计算。缓存主要保存这两部分。读取时，可以从 c_kv 通过 Up Projection（上投影）恢复各 Head 的内容 K/V。

C = XWDKV　　Kc,h = CUK,h　　Vh = CUV,h
Sh = (Qc,hKc,hᵀ + Qr,hKrᵀ) / √(dc+dr) + Mask

权重吸收怎么省计算？ 对内容部分，分数里有 q·(cW_UK)。利用矩阵乘法结合律，可以先把 Q 变换成 q'=qW_UKᵀ，再直接与缓存的 c 做点积。Value 的上投影也可以移动到加权求和之后。这样 Decode 无需显式展开完整内容 K/V。

面试速记：先画 x → c_kv → cache，再区分非吸收式与吸收式的 Decode 数据流。KV 容量按实际缓存的 latent、RoPE 分量和精度估算；Prefill 与 Decode 的最优路径可能不同。

5.4 权重吸收与分块投影

MLA 把历史内容保存成低维 latent。权重吸收利用矩阵乘法结合律，让 Decode 在 latent 空间完成更多计算。

Qc,h(CUK,h)ᵀ = (Qc,hUK,hᵀ)Cᵀ
Ph(CUV,h) = (PhC)UV,h

Decode 的 Q 很短，这样可直接围绕 latent 历史计算，减少完整 K/V 的临时展开。Prefill 的 Q 较长，大矩阵复用和中间状态成本不同，可选择适合该形状的吸收式或展开式路径。

import math
import torch
# safe_softmax 见第 6.1 节；资料包 reference_kernels.py 已包含依赖。

def mla_core(qc, qr, c, kr, uk, uv, wo, *, absorbed=False, query_start=None):
    """Minimal multi-head MLA core, AFTER Q/K projections, normalization and RoPE.
    qc:[B,H,Tq,Dc], qr:[B,H,Tq,Dr], c:[B,Tk,R], kr:[B,Tk,Dr],
    uk:[H,R,Dc], uv:[H,R,Dv], wo:[H*Dv,Dmodel].
    Not a complete DeepSeek model; no YaRN-specific scale correction.
    """
    b,h,tq,dc=qc.shape
    tk, dr=c.shape[1],qr.shape[-1]
    start=tk-tq if query_start is None else query_start
    if start < 0 or start+tq>tk: raise ValueError("Invalid positions")
    if qr.shape[:3]!=(b,h,tq) or kr.shape!=(b,tk,dr):
        raise ValueError("Invalid RoPE shapes")
    if uk.shape!=(h,c.shape[-1],dc) or uv.shape[:2]!=(h,c.shape[-1]):
        raise ValueError("Invalid up-projection shapes")
    if absorbed:
        qlatent=torch.einsum("bhqd,hrd->bhqr",qc,uk)
        score=torch.einsum("bhqr,bkr->bhqk",qlatent,c)
    else:
        kc=torch.einsum("bkr,hrd->bhkd",c,uk)
        vv=torch.einsum("bkr,hrv->bhkv",c,uv)
        score=torch.einsum("bhqd,bhkd->bhqk",qc,kc)
    score += torch.einsum("bhqd,bkd->bhqk",qr,kr)
    score /= math.sqrt(dc+dr)
    allow=torch.arange(tk,device=c.device)[None,:] <= start+torch.arange(tq,device=c.device)[:,None]
    p=safe_softmax(score.masked_fill(~allow,-torch.inf))
    if absorbed:
        latent_out=torch.einsum("bhqk,bkr->bhqr",p,c)
        out=torch.einsum("bhqr,hrv->bhqv",latent_out,uv)
    else:
        out=torch.einsum("bhqk,bhkv->bhqv",p,vv)
    return out.transpose(1,2).reshape(b,tq,-1) @ wo

5.5 GDN 与 KDA：如何遗忘、修正并读取状态

GDN/KDA 将历史关联压缩到固定形状的状态矩阵。先用 Key 读旧预测，再按误差写入；两者主要区别在遗忘门控的粒度。

一、S 是什么？为什么 Delta 要先读再写？

以下固定单个 Head：k, q:[dₖ]，v:[dᵥ]，S:[dₖ,dᵥ]。S 是一张 Key→Value 的关联表。用 Key 读取旧预测 v̂ = Sᵀ k；用 Query 读当前输出 o = Sᵀ q。

如果直接向 S 加 k vᵀ，同一个 Key 多次写入会累积旧内容。Delta Rule 先读取当前记忆，再计算需要修正多少：

旧预测：v̂ = Sᵀ k　[dᵥ]
写入误差：e = v − v̂　[dᵥ]
Delta 更新：S′ = S + β · k eᵀ　[dₖ,dᵥ]
Delta Rule：沿当前 Key 方向纠正记忆
① 读取Sᵀk 得到旧预测 v̂
② 比较目标 v − 旧预测 v̂
③ 写入βk(v−v̂)ᵀ 加到 S
④ 输出新状态 S′ᵀq

β 是写入强度，范围通常为 0～1。若 Key 的二范数为 1，β=1 时对同一个 Key 重新读取会得到目标 v；β=0.5 表示向目标修正一半。真实 Key 之间可能相互干扰，因此模型需要学习合适的特征和门控。

二、GDN：先给整个 Head 的状态乘一个标量

衰减：S̄ₜ = αₜ Sₜ₋₁　（αₜ 为标量）
预测：v̂ₜ = S̄ₜᵀ kₜ
修正：Sₜ = S̄ₜ + βₜ kₜ (vₜ−v̂ₜ)ᵀ
输出：oₜ = Sₜᵀ qₜ

αₜ 越接近 1，旧状态保留越多；越接近 0，遗忘越快。将读取误差代入更新式，便得到论文中的合并写法：

GDN：Sₜ = αₜ (I − βₜ kₜ kₜᵀ) Sₜ₋₁ + βₜ kₜ vₜᵀ

这里 I 是 [dₖ,dₖ] 的单位矩阵；kₜkₜᵀ 是秩一矩阵，表示沿当前 Key 的方向修正。α 控制遗忘，β 控制当前 Key 的写入。

三、KDA：Key 通道分别决定遗忘多少

KDA 将 αₜ 改成长度为 dₖ 的向量。Diag(αₜ) 是由这些系数组成的对角矩阵，乘以 S 相当于按行缩放：S 的第 i 行乘以 αₜ,i。

衰减：S̄ₜ = Diag(α⃗ₜ) Sₜ₋₁　（α⃗ₜ:[dₖ]）
修正：Sₜ = S̄ₜ + βₜ kₜ (vₜ−S̄ₜᵀkₜ)ᵀ
输出：oₜ = Sₜᵀ qₜ
KDA：Sₜ = (I − βₜ kₜ kₜᵀ) Diag(α⃗ₜ) Sₜ₋₁ + βₜ kₜ vₜᵀ

与 GDN 相比，改变的是衰减粒度：一个 Head 不同 Key 特征可以具有不同的保留速度。β 仍是当前 Token、当前 Head 的写入强度标量。α⃗ 和 β 均从输入特征中学习得到。

四、用同一组数字完整计算

取 dₖ=2, dᵥ=1，旧状态 S=[2,10]ᵀ，k=[1,0]ᵀ，目标 v=6，读取用 q=[1,1]ᵀ，写入强度 β=0.5。我们只改变遗忘门控。

五、Prefill 如何并行？Decode 要保存多少状态？

Decode 每产生一个 Token 执行一次上述更新，单层每个 Head 的状态大小为 dₖ×dᵥ，与历史 Token 数无关。Prefill 的递归依赖可通过 Chunkwise（分块并行）算法加速：块内将连续的状态转换重组为矩阵运算，块间传递最终状态。

KDA 的状态转换矩阵可展开成 DPLR（Diagonal-Plus-Low-Rank，对角加低秩）结构：

(I−βkkᵀ)Diag(α⃗) = Diag(α⃗) − β·k(k⊙α⃗)ᵀ

左边按 Token 递推，右边的“对角矩阵＋秩一修正”便于构造块内并行算法。实际高性能实现还涉及短卷积、门控参数化、数据布局和专用 Kernel。

import torch

def delta_step(S, k, v, q, alpha, beta):
    # S:[dk,dv] k,q:[dk] v:[dv]
    # GDN alpha:[]；KDA alpha:[dk]
    if alpha.ndim == 0:
        S_bar = alpha * S
    else:
        S_bar = alpha[:, None] * S
    v_hat = S_bar.T @ k        # [dv]
    error = v - v_hat          # [dv]
    S_new = S_bar + beta * torch.outer(k, error)
    output = S_new.T @ q       # [dv]
    return S_new, output

6.1 稳定 Softmax 与在线更新

分块计算 Softmax 时，后续块可能出现更大的分数。维护最大值、指数和与输出分子，就能把旧结果重新缩放后继续累积。

m′ = max(m, max(S_block))　　α = exp(m−m′)
P_block = exp(S_block−m′)
l′ = αl + ΣP_block　　U′ = αU + P_block V_block
全部块完成后：O = U/l

import torch

def _work_dtype(x):
    return torch.float64 if x.dtype == torch.float64 else torch.float32

def safe_softmax(x: torch.Tensor, dim: int = -1) -> torch.Tensor:
    """Finite logits / -inf masks. Fully masked row returns zero by convention."""
    if not x.is_floating_point() or x.shape[dim] == 0:
        raise ValueError("Nonempty floating-point logits required")
    if torch.isnan(x).any() or torch.isposinf(x).any():
        raise ValueError("NaN / +inf logits are not supported")
    z = x.to(_work_dtype(x))
    m = z.amax(dim=dim, keepdim=True)
    anchor = torch.where(torch.isfinite(m), m, torch.zeros_like(m))
    e = torch.exp(z - anchor)
    den = e.sum(dim=dim, keepdim=True)
    p = e / den.clamp_min(torch.finfo(z.dtype).tiny)
    return p.to(x.dtype)

def online_attention(scores: torch.Tensor, values: torch.Tensor,
                     chunk: int = 3) -> torch.Tensor:
    """scores:[Tq,Tk], values:[Tk,Dv]. Scores may contain -inf masks.
    U is an UNNORMALIZED numerator; final result is U/l.
    """
    if scores.ndim != 2 or values.ndim != 2 or scores.shape[1] != values.shape[0]:
        raise ValueError("Invalid attention shapes")
    if chunk <= 0 or scores.shape[1] == 0:
        raise ValueError("Positive chunk and nonempty keys required")
    if torch.isnan(scores).any() or torch.isposinf(scores).any():
        raise ValueError("NaN / +inf scores unsupported")
    dtype = _work_dtype(scores)
    s, v = scores.to(dtype), values.to(dtype)
    m = torch.full((s.shape[0], 1), -torch.inf, device=s.device, dtype=dtype)
    l = torch.zeros_like(m)
    u = torch.zeros((s.shape[0], v.shape[1]), device=s.device, dtype=dtype)
    for j in range(0, s.shape[1], chunk):
        block = s[:, j:j+chunk]
        mn = torch.maximum(m, block.amax(-1, keepdim=True))
        anchor = torch.where(torch.isfinite(mn), mn, torch.zeros_like(mn))
        alpha = torch.exp(m - anchor)
        p = torch.exp(block - anchor)
        u = alpha * u + p @ v[j:j+chunk]
        l = alpha * l + p.sum(-1, keepdim=True)
        m = mn
    return (u / l.clamp_min(torch.finfo(dtype).tiny)).to(scores.dtype)

6.2 多分片输出与 LSE 归并

每张 GPU 只看一部分 KV 时，局部 Softmax 输出不能直接平均。LSE 记录了每个分片的归一化权重，用它可以合并成全局结果。

L = logsumexp(L₀, L₁, …)
O = Σᵢ exp(Lᵢ−L) Oᵢ
全局指数和 = 8
O = (2/8)×2 + (6/8)×5 = 4.25

也可直接归并 (mᵢ,lᵢ,Uᵢ)：先取全局 m，再用 exp(mᵢ−m) 缩放各自 lᵢ/Uᵢ。每个 Query/Head 独立维护统计量；通信按最终输出的归属组织。

6.3 FlashAttention：为什么分块还需要 Online Softmax？

标准 Attention 先计算 QKᵀ，再 Softmax，最后乘 V。对于长度为 T 的序列，中间分数矩阵大小是 T×T。长上下文时，写入和重新读取这张矩阵会带来大量 HBM 流量。

FlashAttention 按块加载 Q/K/V，在片上完成局部分数、Softmax 和输出累积。问题是：每一块分数的最大值不同，直接把局部 Softmax 输出相加会得到错误结果。因此需要 Online Softmax（在线归一化）。

版本主要优化对象实现要点
FA1中间分数的 HBM 读写Tiling（分块）与在线 Softmax；逐块累积 O
FA2并行度和线程间协作优化 Q/头的工作划分，减少共享内存通信与非矩阵运算
FA3Hopper 异步硬件TMA、WGMMA 与职责分离，交叠搬运、QK/PV 和 Softmax
FA4Blackwell 的片上与非矩阵瓶颈前向优化 exp/重缩放；反向利用 TMEM、2-CTA 等降低部分片上流量
m' = max(m, max(s))
l' = exp(m−m')·l + Σexp(s−m')
u' = exp(m−m')·u + Σexp(s−m')·V
O = u'/l'

对一个 Query，维护三个状态：m 是目前最大分数，l 是以 m 为基准的指数和，u 是尚未除以 l 的加权输出。读到新块后，先更新最大值，再把旧的 l/u 重缩放到新基准，最后加上当前块的贡献。

m' = max(m, max(s))
l' = exp(m−m')·l + Σexp(s−m')
u' = exp(m−m')·u + Σexp(s−m')·V
O = u'/l'

FA4：条件重缩放与 exp 近似

当新块最大值与当前参考值差距较小时，可继续沿用旧参考 m，把新块分子、分母也记在这个尺度；达到触发条件后统一重缩放。保持尺度一致和足够数值裕量，是最终正确归一化的前提。

exp 所用的特殊函数管线可能限制吞吐。FA4 把部分指数计算分配给基于 FMA（乘加）的多项式近似，与硬件指数指令分担工作。阈值、exp/exp2 单位和近似精度按实现配置；数值验收同时看误差与任务质量。

6.4 Flash-Decoding：把长 KV 分给更多 CTA

Flash-Decoding：并行读不同 KV 区间

切 KV历史 128K 拆成多个 KV Chunk

合并局部 max / sum / numerator 精确归并

与 FlashAttention 减少 N² 中间 IO 的动机不同：Flash-Decoding 主要解决短 Q 下的 GPU 并行度不足。

分块数增加带来更多并行，也增加中间结果、归并与启动成本。长 KV、小 Batch 更容易获益；Batch×Head 已提供充分并行或 KV 很短时，可减少拆分。Flash-Decoding 优化一次 Attention，推测解码则提高一次目标模型验证产生的 Token 数。

7.4 三类 Chunk：调度分块、Attention 分块、状态分块

Chunked 可以指调度 Token、分块 Attention 或递归状态更新。先明确切分对象，再看每类 Chunk 的状态如何接续。

② 的合并公式：若每个 KV 分片返回局部归一化输出 Oᵢ 和对数归一化量 LSEᵢ，则

m = maxᵢ LSEᵢ
O = [Σᵢ exp(LSEᵢ−m) · Oᵢ] / [Σᵢ exp(LSEᵢ−m)]

例如两段 KV 的 LSE 分别为 2 和 3，第二段对最终输出的权重更大。归并时保留每段的归一化质量，结果等价于对全部 KV 一起做 Softmax。Online Softmax 在一个 Kernel 内逐块维护统计量；跨 CTA/Rank 时可以用 LSE 归并局部结果。

可执行代码：合并多个 KV 分片的 Attention 输出
import torch

def merge_attention(partial_o, lse):
    # partial_o:[parts, d_v]，每段已经归一化
    # lse:[parts]，每段的 logsumexp(scores)
    weight = torch.softmax(lse, dim=0)  # 数值稳定的分片权重
    return (weight[:, None] * partial_o).sum(dim=0)

# 多 Query/Head 时，对每个 Query/Head 独立执行相同归并。

7.6 P/D 分离与容量规划

Prefill 和 Decode 对 GPU 的需求不同。P/D 分离让它们独立调度和扩容，代价是 KV 迁移、安装与跨池协调。

Agent 请求若已有很长前缀驻留在 D，少量后缀在本地处理可能更便宜；分离部署可通过前缀亲和、增量传输和池间复用减少移动。比较同一服务目标下的总关键路径。

P 需求 ≈ λ × E[实际需 Prefill 的 Token]
D 需求 ≈ λ × E[输出 Token]
实例数 ≈ ceil(需求 / [该负载下实测容量 × 目标利用比例])

算例：100 请求/s，输入均值 2000、有效免算比例 40%、输出均值 500；P 需求 12 万 Token/s，D 为 5 万。若单 P/D 容量分别为 6 万/1.2 万，取 70% 目标利用比例，初估需 3P、6D。继续检查 KV 容量、传输和尾延迟。

Pi 当上下文逼近上限时，按消息边界选择 Cut Point（裁剪点），把较早历史整理成结构化摘要，追加 CompactionEntry（压缩记录），下次请求使用“摘要 + 最近保留消息”。分支切换还有 Branch Summarization（分支摘要）。会话日志保留完整事件，模型输入使用经过压缩的投影；压缩发生后，需要重新建立新前缀的缓存。Pi Compaction 官方文档

10.1 多卡并行：模型到底切在哪里？

先把一层模型拆成三类数据：输入 Token、模型权重和中间激活。不同并行方式切分的对象不同，因此通信位置也不同。

DP（数据并行）让不同 GPU 处理不同 Batch；TP（张量并行）把同一层矩阵切开；PP（流水线并行）把不同网络层分到不同 GPU；CP（上下文并行）分摊序列计算或 KV；EP（专家并行）把 MoE 的 Expert 分散到不同 GPU。

并行轴切分对象典型通信与成本
DP：数据并行不同请求/Batch 使用模型副本推理扩吞吐；训练同步梯度
TP：张量并行层内权重与计算维度AllReduce/AllGather/ReduceScatter，频率高
PP：流水线并行不同网络层相邻阶段传激活/梯度，受流水空泡限制
CP：上下文并行序列计算或历史 KV移动 Q/KV，并归并局部 Attention
EP：专家并行MoE 的专家参数与执行Token Dispatch/Combine，常用 All-to-All

用 TP=2 的 FFN 理解通信：第一层 Linear 沿输出通道切分，GPU 0/1 各算一部分中间特征，激活函数可以在本地完成。第二层沿输入通道切分，两卡分别计算同一个输出的部分和，最后 AllReduce 汇总。经典 TP 的 Attention 输出投影也有类似的归约位置。

面试速记：给定矩阵 Shape，先写出每卡持有什么，再判断需要 AllGather、ReduceScatter 还是 AllReduce；不要先背固定的通信次数。

10.2 TP=2：两次 Linear 为什么只需一次归约？

TP=2 的 FFN 先按输出通道切第一层，再按输入通道切第二层。两卡各算局部贡献，最后一次 AllReduce 合并。

FFN(X) = Σᵢ [ act(XW₁,ᵢ) W₂,ᵢ ]
W₁:[H,4H] 按列切；W₂:[4H,H] 按行切

为什么可以省去第一层后的 AllGather？因为逐元素激活函数对各自的通道独立计算，第二层又恰好消费同一份中间通道。各卡保留局部中间张量，直到输出维度需要相加时再通信。SwiGLU 等门控 FFN 还要把 Gate 与 Up 投影按对应通道配对切分。

NumPy 手算：TP=2 与完整 FFN 输出一致
import numpy as np
rng = np.random.default_rng(0)
x = rng.normal(size=(3, 8))
w1 = rng.normal(size=(8, 32))
w2 = rng.normal(size=(32, 8))
act = lambda z: np.maximum(z, 0)
ref = act(x @ w1) @ w2
w1_parts = np.split(w1, 2, axis=1)  # 输出通道切分
w2_parts = np.split(w2, 2, axis=0)  # 输入通道切分
partial = [act(x @ a) @ b for a, b in zip(w1_parts, w2_parts)]
out = partial[0] + partial[1]      # 模拟 AllReduce sum
np.testing.assert_allclose(ref, out, rtol=1e-12, atol=1e-12)

通信位置：Column Parallel 生成局部特征；Row Parallel 生成需要求和的局部贡献。启用 Sequence Parallel（序列并行）时，部分前向归约可变为 ReduceScatter，下一层再 AllGather 输入；通信原语由输出的分布方式决定。

10.3 集合通信与字节账本

原语结果归属
Broadcast（广播）根 rank 的数据复制给组内全部 rank
AllGather（全收集）各 rank 的分片拼接，所有 rank 获得完整结果
ReduceScatter（归约散发）对应元素归约后，每 rank 只保存一个结果分片
AllReduce（全归约）所有 rank 获得归约后的完整结果
All-to-All（全互换）每个 rank 向各目标发送不同数据，用于重新分布
Ring AllGather：每 rank 原有 S 字节，最终输出 PS
每 rank 发送量 = 接收量 = (P−1)S
Ring AllReduce：每 rank 输入 D 字节，每 rank 发送量 ≈ 2(P−1)D/P

集合通信先算字节账本，再算时间。以 AllGather 为例，完整输出大小、每卡传输量和额外缓冲区是三个不同指标。

10.4 上下文并行：传 Q 还是传 KV？

长上下文 Attention 需要让一个 Query 看到分布在多个 GPU 上的历史 KV。我们先假设每张 GPU 持有一段连续的 KV。接下来有两种典型组织方式。

Pass-KV / Ring：每张卡保留自己的 Q，轮流接收其他卡的 KV 分片，边计算边用 Online Softmax 合并结果。Pass-Q / KV Owner：KV 保留在各自 GPU 上，把 Q 发给 KV Owner；每张卡计算局部输出和 LSE，最后合并。

比较对象：传 Q 的字节 + O/LSE 归并成本
对比：传 KV 的字节 + 分块计算/重叠成本

选择取决于 Q 长度和实际通信字节。长 Q 的 Prefill 计算较多，Ring 的 KV 传输有机会与计算重叠；短 Q 的 Decode 计算较少，移动 Q 并在 KV Owner 本地计算可能更合适。具体还要看 MLA 的缓存布局、TP/CP 通信组、网络拓扑和 Kernel 实现。

面试速记：先画出 KV Owner，再标 Q、KV、局部输出与 LSE 的移动方向。比较传输字节、归并次数和端到端延迟。

PCP、DCP 与模型版本

框架中 PCP/DCP 的组定义与缓存归属分别查配置。例如 vLLM v0.27.1 的 PCP 扩大并行 Prefill 进程规模，而 KV shard count 另由对应规则决定；DCP 可复用 TP ranks。选择方案时记录固定版本、头数/latent 维度和布局。

稀疏注意力也要区分模型版本：DeepSeek V3.1、V3.2-Exp 的 DSA（DeepSeek 稀疏注意力）以及 NSA（原生稀疏注意力研究）分别识别。Ascend 的设备形态、可用 HBM 和并行后端从实际型号与部署信息读取。

10.5 通信计算重叠与 Flux

通信和计算放在不同 Stream 只提供并发可能。GEMM 与 NCCL 仍会竞争 SM、L2 和 HBM，关键看重叠后总时间是否下降。

Flux等细粒度方案把 Tile 的数据就绪与 GEMM 调度关联：一部分输入到达即可启动对应计算，或在输出尾处理阶段推进归约。重点是缩小依赖粒度和传递完成信号。验证时看暴露通信时间、重叠后的矩阵速度和总关键路径。

10.6 MoE 执行、通信量与负载均衡

MoE 的 Token 先经 Router 选择 Expert，再 Dispatch、执行专家 GEMM、Combine。每个 Expert 收到多少 Token，决定负载均衡和通信成本。

均匀路由下：每 expert 平均 Token 数 = B_global × K / E
每源 rank 的远端 Dispatch payload ≈ B_local × K × H × b × f_remote

式中 E 是专家数、H 是隐藏维度、b 是元素字节、f_remote 是远端比例。Combine 另按输出精度统计；目标 rank 内去重、共享专家、Scale、索引和对齐会改变实际流量。

算例：固定每 rank 16 Token、E=256、K=8，EP 组为 P 个 rank，则每 expert 均值为 P/2：P=8/32/64 对应 4/16/32 Token。这里总 Batch 随 P 增长；固定全局 Batch 时，EP 单独增加不会增加该均值。

负载不均来自路由偏斜、局部小批量和长尾专家。训练侧可用均衡损失或容量约束；推理侧可用专家放置/副本、路由感知调度和更细 Tile。副本增加权重存储与同步，效果同时看最慢 rank 和通信。

接着看：DeepEP 与 Grouped GEMM

10.7 DeepEP 与 Grouped GEMM

DeepEP 优化 Token 的 Dispatch/Combine，Grouped GEMM 优化各 Expert 的矩阵计算。沿 MoE 数据流就能看到两者的分工。

Grouped GEMM（分组矩阵乘）把多个专家的不同 M 合并调度；N/K 通常相同。Contiguous（紧凑布局）拼接各专家行段并附边界；Masked（掩码布局）预留容量，由设备侧有效计数控制计算，便于动态 Token 数与 CUDA Graph 配合。

调度先根据各专家的有效行数计算 Tile 数和前缀和，再把全局 Tile ID 映射为 expert、行块、列块。按 M 对齐产生的填充、Scale 排布、L2 复用和尾部 Tile 都计入成本。大 EP 的选型同时考虑每专家批量、权重容量、跨节点 A2A 和最慢专家。

10.9 TP + CUDA Graph 的通信顺序与 Hang

TP 下各 Rank 的 Collective 顺序必须匹配。CUDA Graph 捕获和重放改变执行路径时，要检查 Rank、Stream 和 Event 的依赖是否一致。

两 Rank Graph Replay 的对齐
Rank 0：Graph AGEMM → AllReduce #1 → GEMM
Rank 1：Graph AGEMM → AllReduce #1 → GEMM
通信依赖相同 Group、参与者、Count/DType 和匹配顺序
结束重放Rank 均可继续消费归约结果

若某 Rank 跳过 Graph、使用不同 Collective 序列或提前等待对方尚未提交的工作，可能产生 Hang。

最小排查顺序观测证据
1. TP=1、Eager单卡路径本身是否可执行
2. TP=2、EagerCollective 参数与通信顺序是否正确
3. TP=2、Graph各 Rank 捕获了哪条路径、重放次数和顺序
4. Graph 与非 Graph 混合分桶命中、Fallback 以及多个 Communicator 的调用顺序

修复时把 Graph 选择、Buffer 就绪、Collective 发起、事件记录拆开检查。保留可切换的 Eager 回退路径；对不同 Batch Bucket、并发负载、TP 规模和故障重启重复测试。NCCL 文档也提示，多 GPU/进程的 Graph 捕获、多个通信组混合重放存在额外死锁风险。

11.3 AdamW、归一化与混合精度

训练一步包含梯度计算、缩放/裁剪和参数更新。AdamW、AMP 和归一化分别影响优化规则、数值范围与模型计算。

LayerNorm(x) = γ·(x−μ)/√(σ²+ε) + β
RMSNorm(x) = γ·x/√(mean(x²)+ε)

归一化中的归约通常使用较高内部精度。梯度裁剪作用于更新前的梯度，数值溢出、数据错误和学习率问题仍按各自原因处理。Pre-Norm/Post-Norm 表示归一化与残差分支的相对位置。

AMP 与梯度裁剪

AMP（自动混合精度）按算子选精度。FP16 的 Loss Scaling（损失缩放）缓解梯度下溢，裁剪前先 unscale；BF16 指数范围较宽，通常较少需要缩放。

scaler.update()
# 注意 norm_before 是裁剪前的总范数
裁剪系数 = min(1, max_norm / (‖g‖ + ε))

12.1 SFT、PPO、GRPO 与概率身份

SFT 使用监督目标，PPO/GRPO 使用采样轨迹与奖励更新策略。比较算法时先看训练目标、优势估计和行为策略概率。

典型组优势 Aᵢ = (rᵢ − mean(r_group)) / (std(r_group)+ε)
概率比 ρ = exp(logπ_current(a|s) − logπ_behavior(a|s))
PPO 代理目标包含 min(ρA, clip(ρ,1−ε,1+ε)A)

Behavior Policy（行为策略）实际生成样本；冻结的 Old Policy（旧策略）用于算法定义的比值；Reference Policy（参考策略）常用于 KL 约束。记录动作、上下文、掩码、版本与约定的采样概率，温度/top-p 造成的分布变换也要与训练目标一致。

12.4 MoE Router Replay：从 Rollout 到 Trainer

Rollout 与 Trainer 的 MoE Router 可能因数值和执行差异选择不同 Expert。Router Replay 记录逻辑路由选择，让训练侧重放对应计算路径。

Route 索引的端到端数据流
Rollout RouterToken × MoE Layer × TopK
记录 Expert ID
数据编码紧凑整数、Token 身份、策略版本、有效位
Batch / Transfer打包、传输、Sequence/TP/CP 重排
Trainer Forward加载同一 Token 的 Expert 选择；重算 Logits 与门控权重
BackwardActivation Recompute 复用该次选择

专家索引用逻辑 Expert ID 表示；物理 EP Rank 与具体专家放置可以变化，消费端负责把逻辑编号映射到本地执行。

示意：route[t,layer,:] = [17,42]，Trainer 自行 TopK 得到 [17,39]。
Replay 固定选中集合 {17,42}，但该集合上的组合权重由当前 Trainer Logits 决定。

对采用选中专家 Softmax 归一化的 Router，训练时可计算 wₑ = exp(logitₑ) / Σⱼ∈R exp(logitⱼ)，其中 R 来自记录的 TopK。其他 Router（如 sigmoid 门控）使用其对应的权重规则。选中索引来自 Rollout，Router 权重仍参与梯度计算。

需要保存或校验原因
Token / Request / Layer 身份Batch 重新排列、Padding/Sequence Packing 后恢复正确的行
逻辑 Expert ID、TopK 顺序与有效位恢复选中集合、对应权重及无效位置
采样 Policy Version、模型路由配置区分数值差异、参数更新与拓扑变化
TP/EP/CP 的分片映射Rollout 全局 Token 顺序映射到训练侧局部 Microbatch

容量估算：假设每条轨迹 4096 Token、32 个 MoE 层、TopK=8、逻辑专家数 256，使用 uint8 存储选择索引，则索引主体是 4096×32×8×1 = 1,048,576 B，即 1 MiB/轨迹。实际还包含长度、Mask、版本与传输格式等元数据；若需要额外无效标记或 Expert 数超过 256，编码须相应调整。阿里 ROLL 有按专家数选择 uint8/int16 的实现示例。

验证指标测量目标
Router Mismatch Rate同一 Token/Layer，Rollout 与 Trainer 自由路由的 Expert 集合差异
Logprob Gap同一有效 Token 的 Rollout Logprob 与训练侧重算值差异
Policy KL选定两种策略分布之间的差异；明确 old/current/reference 与 full-KL/采样估计口径
Gradient / Update Check路由权重是否仍有梯度、更新是否发生、训练质量是否稳定

R3 消除了“这批历史轨迹使用了哪组 Expert”这一来源的差异；训练侧的 Router Logits、浮点算子、通信归约、随机种子，以及策略更新带来的陈旧性仍须单独控制。R3 在 Off-policy 多次更新中也可能改变路由梯度的有效支持集，需要结合算法目标验证。Router Drift Control（2026）进一步讨论了这一取舍。

两道追问：TopK 和 KL 为什么必须分别测？

TopK 是离散选择，一处翻转就会改变 Expert 计算图；KL 则衡量最终概率分布差异。两者可以相关，但不会彼此唯一决定。调试时还要控制权重版本、有效 Token Mask、Token 对齐、归一化口径和采样温度。

TP/EP 影响的是物理计算和通信：逻辑 Expert ID 对应的权重如何分片、Token 如何 Dispatch/Combine；Replay 固定逻辑选择之后，物理通信中的数值顺序差异依旧存在。

工具结果是后续模型决策的观察条件；被训练的动作和环境生成的观察按损失目标使用不同掩码。

KV 是可重算的推理状态；Trajectory 的 Token、动作掩码、采样策略和工具结果是训练语义的一部分，跨版本消费需单独检查。

13　C++、操作系统与并发

C++ 与操作系统基础围绕一个问题：数据由谁持有、何时可见、何时释放。内存、线程和并发原语都能放到这条线上。

13.1 进程、线程与协程

进程提供隔离，线程共享地址空间，协程在运行时定义的挂起点切换。选择哪种并发方式，取决于工作是等待 I/O 还是持续占用 CPU。

启用 GIL（全局解释器锁）的 CPython 中，纯 Python 计算线程通常竞争解释器锁；I/O 和释放 GIL 的原生库可并发推进，free-threaded 构建另有实现。阻塞调用或长时间计算会占住协程事件循环。

单核上多线程可能在一个线程等待 I/O 或内存时推进另一个工作；纯计算且已充分利用执行资源时，新增线程主要增加切换与竞争。SMT（同时多线程）的收益也取决于可利用的执行空隙。

接着看：虚拟内存、缺页与 mmap

13.2 虚拟内存、缺页与 mmap

进程访问的是虚拟地址，页表负责映射，TLB 缓存地址转换。mmap 建立映射后，实际数据页可能在首次访问时才被调入。

Page Cache（页缓存）存放文件数据。映射可减少传统 read 路径的用户态复制，首次访问仍可能付出缺页与存储成本。MAP_SHARED 共享修改，MAP_PRIVATE 写入采用私有语义；文件截短后继续访问原映射可能触发错误。

机制主要作用调优条件

    std::string payload;
    std::atomic<bool> ready{false};
    std::thread producer([&] {
        payload = "complete-data";
        ready.store(true, std::memory_order_release);
    });
    std::thread consumer([&] {
        while (!ready.load(std::memory_order_acquire)) {
            std::this_thread::yield();
        }
        assert(payload == "complete-data");
    });
    producer.join();
    consumer.join();
}

relaxed只提供相应原子对象的原子性；C++ volatile用于特殊访问语义，不承担线程间同步。CPU 原子协议、CUDA 事件与 RDMA 完成协议分别在各自的内存与执行模型下使用。

13.5 锁、CAS、引用计数与 RCU

锁、CAS、引用计数和 RCU 分别解决不同的并发问题。先明确谁能访问对象，再设计更新与回收顺序。

CAS（比较并交换）只比较当前值；地址经历 A→B→A 会造成 ABA。版本标签识别代际变化，Hazard Pointer（危险指针）或 Epoch（代际回收）保护仍被读取的对象。

引用计数保护所有权生命周期，数据内部并发读写另需协议。RCU（读、复制、更新）先发布新指针，等待旧读者宽限期结束后回收旧对象。交给异步 GPU/NIC 的缓冲区也要保留到实际消费完成，再归还内存池。

#include <utility>

class Buffer {
    std::size_t n_ = 0;
    std::unique_ptr<int[]> data_;
public:
    explicit Buffer(std::size_t n = 0)
        : n_(n), data_(n ? std::make_unique<int[]>(n) : nullptr) {}
    Buffer(const Buffer& other) : Buffer(other.n_) {
        if (n_) std::copy_n(other.data_.get(), n_, data_.get());
    }
    Buffer(Buffer&& other) noexcept

    void swap(Buffer& other) noexcept {
        std::swap(n_, other.n_); data_.swap(other.data_);
    }
    Buffer& operator=(Buffer other) noexcept { swap(other); return *this; }
    int& operator[](std::size_t i) { return data_[i]; }
    const int& operator[](std::size_t i) const { return data_[i]; }

14.3 带宽时延积与 Little 定律

T_transfer ≳ 启动延迟 + Bytes / 有效带宽
BDP（带宽时延积）= 链路带宽 × RTT
Little 定律：L = λW（稳定系统的平均在途量）

GB 与 GiB、bit/s 与 Byte/s 分别统一单位。Little 定律用平均值；尾延迟另从排队、服务时长分布和扇出分析。

16.2 租约与 Fencing Token

16.4 至少一次、幂等与外部副作用

失败窗口处理
业务生效后，响应丢失用稳定幂等键重试或查询原结果
写去重记录后，业务还没执行就崩溃把状态转移与效果纳入同一原子边界
本地提交后，外部消息尚未发送Outbox（事务发件箱）持久记录待发事件

Exactly-once（恰好一次）应标明覆盖消息、状态变更还是外部效果。去重记录保留时间至少覆盖可能的重试窗口，相同键携带不同参数时按协议拒绝或识别冲突。

def copyRandomList(head):
    if not head: return None
    p=head
    while p:
        node=Node(p.val,p.next)
        p.next=node
        p=node.next
    p=head
    while p:
        p.next.random = p.random.next if p.random else None
        p=p.next.next
    dummy=Node(0); tail=dummy; p=head
    while p:
        q=p.next
        p.next=q.next
        tail.next=q; tail=q
        p=p.next
    return dummy.next

19.3 兑换题与多核任务调度

兑换题用不变量计数，任务调度题先算总工作量与最长任务的下界。先判断是否可整除，再考虑分配策略。

任务1…N，耗时分别为1…N，总工作W=N(N+1)/2
K个相同核、任务不可拆：完成时间下界 ≥ max(N, ceil(W/K))

固定 K 时关注最小完成时间；给定时间上限 T 时，核数至少 ceil(W/T)，且 T≥N。LPT（最长任务优先）把任务从长到短放入当前最空闲核，给出可行近似；严格最优需利用题目约束另行求解。

LPT：最小堆维护每核累计负载
# LPT 贪心近似：最小堆维护当前每核负载
import heapq
loads = [(0, i) for i in range(K)]
heapq.heapify(loads)
for duration in range(N,0,-1):
    used, i=heapq.heappop(loads)
    heapq.heappush(loads,(used+duration,i))
answer=max(x for x,i in loads)

19.4 LC 2712 与机器选择

贪心题先找局部决策如何影响全局目标。LC 2712 可从相邻边界变化推导；机器选择则按限制因素排序。

最小翻转代价
def minimumCost(s):
    n=len(s)
    return sum(min(i,n-i) for i in range(1,n) if s[i]!=s[i-1])

最多选择 K 台机器，使 Σspeed×min(reliability) 最大：按 reliability 降序扫描，当前值作为最小可靠性候选；最小堆维护至多 K 个最大的 speed，累计和乘当前 reliability 更新答案。时间 O(n log n+n log K)，适用正速度与非负可靠性。

19.5 数字字符串插加号：所有表达式之和

数字字符串插加号时，每读入一个数字都有“接在上一段后”和“新开一段”两种选择。维护表达式总和与最后一段贡献即可递推。

total′ = 2total + 9last + 2count·d
last′ = 10last + 2count·d　　count′ = 2count
线性状态转移；大整数或按题目要求取模
def sum_with_pluses(s: str) -> int:
    if not s or any(ch < '0' or ch > '9' for ch in s):
        raise ValueError("需要非空十进制数字串")
    total = last = int(s[0])
    count = 1
    for ch in s[1:]:
        d = int(ch)
        total, last = 2*total + 9*last + 2*count*d, 10*last + 2*count*d
        count *= 2
    return total
