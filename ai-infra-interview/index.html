01　性能测量与诊断

先固定负载和测量口径，再沿请求时间线定位成本。工具分别观察框架算子、系统执行和 GPU 内核三个层次。

1.1 延迟、吞吐与 MFU

推理通过 Prefill（预填充）处理输入，再由 Decode（逐步解码）生成 Token（词元）。服务至少同时观察首 Token 延迟 TTFT、Token 间隔 ITL、每输出 Token 平均耗时 TPOT和吞吐。TTFT 包含排队、输入处理与首次生成；TPOT 常按首 Token 之后的时间除以剩余输出数计算。服务目标用 SLO（服务级目标）表达，例如 P99 TTFT 上限；Goodput（有效吞吐）统计满足这些约束的请求或 Token。

MFU = Fmodel / (Δt × GPU 数量 × 单卡匹配精度的峰值 FLOP/s)

MFU（模型浮点计算利用率）统计有效模型计算；HFU（硬件浮点利用率）可包含激活重算等额外计算。分母选相同精度和稠密/稀疏口径，MoE 按实际激活的专家估算。Decode 还要结合带宽与延迟判断效率。

记录项固定或报告什么
负载模型/权重版本、输入与输出长度分布、并发或到达率、采样参数
资源GPU 型号与数量、精度、并行组、功耗/频率、软件版本
统计预热后测量、多轮重复；报告中位数与尾部、成功率及质量
缓存冷启动、热缓存、按 Token 统计的有效免算比例分别记录

1.2 四类瓶颈与第一轮判断

一次慢请求可能包含多种瓶颈。先按下面的现象形成假设，再用针对性实验检查：改变 Batch（批量）、减少搬运、移除同步，观察哪一项真正改变总时间。

瓶颈常见证据优先检查
计算受限某计算管线吞吐接近可持续上限矩阵精度、指令数量、Tile（分块）形状和流水
带宽受限HBM（高带宽显存）、L2 或共享内存中某一级搬运繁忙字节数、合并访存、数据复用、融合和量化
延迟受限吞吐有余量，可发射线程束少、依赖等待长寄存器占用、独立工作、预取距离和屏障
系统受限CPU/GPU 空隙、排队、通信等待或慢节点提交、同步、通信组、调度和负载均衡

Roofline（屋顶线模型）给出计算与带宽的性能上界；依赖等待、启动开销和通信会让实际性能落在上界以下。优化后重新看时间线，热点可能已经改变。

1.4 Roofline 与 GEMM 批量估算

算术强度 AI表示每搬运一字节所完成的浮点运算。对某一存储层级，性能上界由计算吞吐 P 和带宽 BW 中更紧的约束决定。

AI = FLOPs / Bytes　　Performance ≤ min(P, BW × AI)　　交叉点 R = P / BW

对于 A[M,K] × W[K,N]，按权重读取一次、输入读取一次、输出写入一次估算，权重每元素 bw 字节，输入与输出每元素 ba 字节：

F ≈ 2MKN
Bytes ≈ KNbw + M(K+N)ba
Mcross ≈ RKNbw / [2KN − R(K+N)ba]

算例：K=7168、N=2048、bw=ba=2、R=200 FLOPs/Byte，交叉 M 约为 229。分母为正时才有这个交叉点。它帮助选择 Batch 扫描范围；最终配置再结合 Tile 对齐、缓存、尾延迟与显存测量。完整计算路径见 3.1 GEMM 分块。

02　CPU/GPU 执行与存储层次

先分清执行单位、存储的共享范围和访问路径。容量限制决定能驻留多少工作，带宽和依赖决定这些工作推进得多快。

Grid、Block、Warp 与 SM延迟隐藏与 OccupancyCPU 缓存与 GPU 两条数据路径容量、延迟与带宽数量级合并访存、Bank Conflict 与地址重排GPU 地址空间与进程共享

2.1 Grid、Block、Warp 与 SM

CUDA 启动一个 Grid（线程网格），其中包含多个 Block/CTA（线程块）。一个线程块在单个 SM（流式多处理器）上执行，线程按线性编号组成 32 线程的 Warp（线程束）。SM 可同时驻留多个 Block，调度器从就绪 Warp 发射指令。

SIMT（单指令多线程）让程序按线程编写标量逻辑，硬件组织线程协作执行。Warp 中的分支用活跃掩码控制，各路径占用执行时间；让同一 Warp 的线程走相同路径通常更高效。共享数据的可见性仍通过同步原语建立。

linear_tid = threadIdx.x + blockDim.x × (threadIdx.y + blockDim.y × threadIdx.z)
warp_id = linear_tid / 32　　lane_id = linear_tid % 32

2.2 延迟隐藏与 Occupancy

一个 Warp 等待内存结果时，SM 可以执行其他就绪 Warp；单个线程中的独立指令也能提供并行工作。这叫 Latency Hiding（延迟隐藏）。

概念读指标时的含义
Resident Warp（驻留线程束）状态和资源已分配在 SM 上
Eligible Warp（可发射线程束）依赖满足、当前可被调度
Issued Warp（已发射线程束）本周期实际提交了指令
Occupancy（占用率）活跃 Warp 数相对硬件上限的比例

每个 Block 的寄存器、SMEM 和线程数量共同约束驻留数量。算例：SM 有 65,536 个 32-bit 寄存器，Block 为 256 线程；每线程 64 个寄存器耗用 16,384 个，按该预算可放 4 个 Block；每线程 128 个时变为 2 个。实际还受分配粒度和其他资源约束。

2.3 CPU 缓存与 GPU 两条数据路径

CPU 的普通加载通过 L1/L2/L3 Cache（硬件缓存）复用数据，未命中时访问 DRAM。缓存以 Cache Line（缓存行）为单位搬运数据；寄存器存放指令操作数。GPU 的普通全局加载也使用缓存，同时提供程序显式分配的 Shared Memory/SMEM（共享内存），供线程块协作复用。

GPU 的 L1/SMEM 常共享片上物理容量，管理方式不同。普通加载可经过缓存到寄存器；cp.async 或 TMA 可把全局数据直接搬到 SMEM。数据命中某一级缓存后，访问就在该层完成。

2.5 合并访存、Bank Conflict 与地址重排

32-bit 标量读取：bank = (byte_address / 4) mod 32
shared[tid × stride]：不同 word、完整 Warp 时，冲突度 = gcd(stride,32)

按列读 tile[32][32] 时行跨度为 32 个 float，地址落在同一 bank。改为 tile[32][33] 后，bank 随行号移动。Padding（填充）改变跨度；Swizzle（布局重排）改变逻辑坐标到物理地址的映射。一个 32×32 float 教学布局可用 physical_col = col ^ row，按行和按列访问都能分散到 32 个 bank。

#include <algorithm>
#include <array>
#include <cstdint>
#include <stdexcept>
#include <unordered_set>
#include <vector>

// One warp; aligned scalar 32-bit READS only.
// Multiple lanes reading the same word are a broadcast.
int bank_degree(const std::vector<std::uint64_t>& byte_addresses) {
    if (byte_addresses.size() > 32) throw std::invalid_argument("at most 32 lanes");
    std::array<std::unordered_set<std::uint64_t>, 32> words;
    for (auto addr : byte_addresses) {
        if (addr % 4 != 0) throw std::invalid_argument("unaligned");
        auto word = addr / 4;
        words[word % 32].insert(word);
    }
    int waves = 0;
    for (const auto& bank : words)
        waves = std::max(waves, static_cast<int>(bank.size()));
    return waves;  // 0=no active lanes; 1=conflict free
}

3.1 用同一组矩阵理解三级分块

GEMM（通用矩阵乘）在本章取 C=A×B，A[M,K]、B[K,N]、C[M,N]，运算量约 2MKN。朴素实现让每个线程计算一个 C 元素；同一行 A 和同一列 B 会被多个线程反复请求。分块把共享输入搬到更近的存储，让一次搬运服务多个输出。

层级工作与复用
Block Tile一个线程块负责 B_M×B_N 的输出；合作加载 B_M×B_K 与 B_K×B_N 输入
Warp Tile线程束协作完成子块，适配矩阵指令与共享内存布局
Thread/Register Tile线程持有局部操作数和累加值，提高寄存器内复用
每个 K 阶段：C_tile += A[m:m+B_M, k:k+B_K] × B[k:k+B_K, n:n+B_N]

import torch

def _work_dtype(x):
    return torch.float64 if x.dtype == torch.float64 else torch.float32

def tiled_gemm(a,b,bm=3,bn=4,bk=2):
    """CPU 分块矩阵乘参考，用于形状与数值对照。"""
    if a.ndim!=2 or b.ndim!=2 or a.shape[1]!=b.shape[0]:
        raise ValueError("Invalid GEMM dimensions")
    if min(bm,bn,bk)<=0: raise ValueError("Positive tiles required")
    dtype=_work_dtype(a); a,b=a.to(dtype),b.to(dtype)
    m,k=a.shape; n=b.shape[1]
    out=torch.zeros((m,n),dtype=dtype,device=a.device)
    for i in range(0,m,bm):
        for j in range(0,n,bn):
            for t in range(0,k,bk):
                out[i:i+bm,j:j+bn] += a[i:i+bm,t:t+bk] @ b[t:t+bk,j:j+bn]
    return out

多阶段 SMEM ≈ stages × 输入/阶段 + scale/屏障/临时区

3.4 Warp、Block 与 Two-pass Reduction

Reduction（归约）把多个元素合成一个结果，例如行求和。线程先积累自己的数据，Warp 用 Shuffle（线程束内寄存器交换）归约，再经 SMEM 合并各 Warp 的结果。行很长时，让多个 CTA 分担，再用第二个 Kernel 合并 Partial Sum（局部和）。

CUDA C++：两阶段行归约；代码覆盖 BLOCK=256、每段512、分段数≤256
// 前提：BLOCK=256；chunk_size=512；G=ceil(N/chunk_size) <= 256。
// 第一个 Kernel：每个 (row, part) 独立求一个部分和。
__global__ void row_partial(const float* x, float* tmp,
                            int N, int G, int chunk_size) {
    int row = blockIdx.y, part = blockIdx.x;
    int tid = threadIdx.x;
    __shared__ float buf[256];
    float v = 0.f;
    int end = min(N, (part + 1) * chunk_size);
    for (int c = part * chunk_size + tid; c < end; c += 256)
        v += x[row * N + c];
    buf[tid] = v;
    __syncthreads();
    for (int d = 128; d > 0; d >>= 1) {
        if (tid < d) buf[tid] += buf[tid + d];
        __syncthreads();
    }
    if (tid == 0) tmp[row * G + part] = buf[0];
}

// 第二个 Kernel：每行一个 CTA，归并该行的 G 个部分和。
__global__ void row_finish(const float* tmp, float* y, int G) {
    int row = blockIdx.x, tid = threadIdx.x;
    __shared__ float buf[256];
    buf[tid] = tid < G ? tmp[row * G + tid] : 0.f;
    __syncthreads();
    for (int d = 128; d > 0; d >>= 1) {
        if (tid < d) buf[tid] += buf[tid + d];
        __syncthreads();
    }
    if (tid == 0) y[row] = buf[0];
}

// G=(N+511)/512；先 launch row_partial(grid=(G,M), block=256)，
// 再 launch row_finish(grid=M, block=256)，二者在同一 CUDA stream。
// 如果 G>256，需要增加中间归约层，不能直接用此第二步。

两阶段增加了中间缓冲和一次启动，换来更大的行内并行度与明确的归约顺序。小 N 可由一个 CTA 完成；更大 N 可递归增加层级。AtomicAdd（原子加）提供单次更新原子性，其到达次序会影响浮点舍入。

import math
import torch

def _work_dtype(x):
    return torch.float64 if x.dtype == torch.float64 else torch.float32

def safe_softmax(x: torch.Tensor, dim: int = -1) -> torch.Tensor:
    """Finite logits / -inf masks. Fully masked row returns zero by convention."""
    if not x.is_floating_point() or x.shape[dim] == 0:
        raise ValueError("Nonempty floating-point logits required")
    if torch.isnan(x).any() or torch.isposinf(x).any():
        raise ValueError("NaN / +inf logits are not supported")
    z = x.to(_work_dtype(x))
    m = z.amax(dim=dim, keepdim=True)
    anchor = torch.where(torch.isfinite(m), m, torch.zeros_like(m))
    e = torch.exp(z - anchor)
    den = e.sum(dim=dim, keepdim=True)
    p = e / den.clamp_min(torch.finfo(z.dtype).tiny)
    return p.to(x.dtype)

def causal_mha(q: torch.Tensor, k: torch.Tensor, v: torch.Tensor,
               *, query_start: int | None = None) -> torch.Tensor:
    """q:[B,H,Tq,D], k:[B,H,Tk,D], v:[B,H,Tk,Dv].
    Keys are positions 0..Tk-1. By default q is the suffix of the cache.
    No padding, sliding window, GQA, dropout or production cache manager.
    """
    if q.ndim != 4 or k.ndim != 4 or v.ndim != 4:
        raise ValueError("Expected rank-4 tensors")
    if q.shape[:2] != k.shape[:2] or k.shape[:3] != v.shape[:3]:
        raise ValueError("Batch/head/sequence dimensions do not match")
    if q.shape[-1] != k.shape[-1] or q.device != k.device or k.device != v.device:
        raise ValueError("Q/K dimension or devices do not match")
    tq, tk = q.shape[-2], k.shape[-2]
    start = tk - tq if query_start is None else query_start
    if tq == 0 or tk == 0 or start < 0 or start + tq > tk:
        raise ValueError("Queries must lie within the cached key positions")
    allow = torch.arange(tk, device=q.device)[None, :] <= (
        start + torch.arange(tq, device=q.device)[:, None])
    dtype = _work_dtype(q)
    score = q.to(dtype) @ k.to(dtype).transpose(-1, -2)
    score = (score / math.sqrt(q.shape[-1])).masked_fill(~allow, -torch.inf)
    return (safe_softmax(score) @ v.to(dtype)).to(q.dtype)

5.2 MHA、MQA 与 GQA

MHA（多头注意力）为每个 Q 头保留独立 K/V 头；MQA（多查询注意力）让全部 Q 头共享一组 K/V；GQA（分组查询注意力）让若干 Q 头共享一个 KV 头。共享程度越高，每 Token 的缓存越小。它们属于模型结构，部署时使用相应训练权重。

KV_bytes = 2 × layers × tokens × KV_heads × head_dim × bytes/element

算例：32 层、8 个 KV 头、维度 128、128K Token、BF16，每请求 KV payload 为 16 GiB。并行分片后每 rank 的大小取决于 KV 头是否分片或复制，另需计入页内空余、Scale 和通信缓冲。

Decode 的算术强度推导

B 个互不共享历史的请求，各有一个 Q，历史长度 T，Q/KV 头数为 Hq/Hkv、头维度 D、元素大小 b；忽略投影、Softmax 和缓存命中：

Attention FLOPs ≈ 4BHqTD
KV Bytes ≈ 2BHkvTDb
AI ≈ 2Hq / (Hkv b)

这个式子假设内核在多个 Q 头之间复用共享 KV。MLA 的潜变量计算使用不同维度，另按实际路径估算。

5.3 MLA：潜变量缓存与解耦 RoPE

MLA（多头潜在注意力）把历史内容压缩成较低维的 latent（潜变量）。输入经下投影得到 cKV；内容 K/V 可由上投影恢复。位置相关 K 单独经过 RoPE，缓存主要保存 cKV 和较小的 kR。

C = XWDKV　　Kc,h = CUK,h　　Vh = CUV,h
Sh = (Qc,hKc,hᵀ + Qr,hKrᵀ) / √(dc+dr) + Mask

内容与位置分开后，内容投影可按矩阵结合律重排。潜变量缓存通常没有独立的 head 轴，但每个 Q 头仍有自己的内容投影与注意力分布。缓存容量按 layers×tokens×(latent_dim+rope_dim)×bytes 估算。

5.4 权重吸收与分块投影

Weight Absorption（权重吸收）把长历史的上投影挪到较短的 Q 和输出路径：

Qc,h(CUK,h)ᵀ = (Qc,hUK,hᵀ)Cᵀ
Ph(CUV,h) = (PhC)UV,h

Decode 的 Q 很短，这样可直接围绕 latent 历史计算，减少完整 K/V 的临时展开。Prefill 的 Q 较长，大矩阵复用和中间状态成本不同，可选择适合该形状的吸收式或展开式路径。

PyTorch：展开与吸收两条 MLA 核心路径
import math
import torch
# safe_softmax 见第 6.1 节；资料包 reference_kernels.py 已包含依赖。

def mla_core(qc, qr, c, kr, uk, uv, wo, *, absorbed=False, query_start=None):
    """Minimal multi-head MLA core, AFTER Q/K projections, normalization and RoPE.
    qc:[B,H,Tq,Dc], qr:[B,H,Tq,Dr], c:[B,Tk,R], kr:[B,Tk,Dr],
    uk:[H,R,Dc], uv:[H,R,Dv], wo:[H*Dv,Dmodel].
    Not a complete DeepSeek model; no YaRN-specific scale correction.
    """
    b,h,tq,dc=qc.shape
    tk, dr=c.shape[1],qr.shape[-1]
    start=tk-tq if query_start is None else query_start
    if start < 0 or start+tq>tk: raise ValueError("Invalid positions")
    if qr.shape[:3]!=(b,h,tq) or kr.shape!=(b,tk,dr):
        raise ValueError("Invalid RoPE shapes")
    if uk.shape!=(h,c.shape[-1],dc) or uv.shape[:2]!=(h,c.shape[-1]):
        raise ValueError("Invalid up-projection shapes")
    if absorbed:
        qlatent=torch.einsum("bhqd,hrd->bhqr",qc,uk)
        score=torch.einsum("bhqr,bkr->bhqk",qlatent,c)
    else:
        kc=torch.einsum("bkr,hrd->bhkd",c,uk)
        vv=torch.einsum("bkr,hrv->bhkv",c,uv)
        score=torch.einsum("bhqd,bhkd->bhqk",qc,kc)
    score += torch.einsum("bhqd,bkd->bhqk",qr,kr)
    score /= math.sqrt(dc+dr)
    allow=torch.arange(tk,device=c.device)[None,:] <= start+torch.arange(tq,device=c.device)[:,None]
    p=safe_softmax(score.masked_fill(~allow,-torch.inf))
    if absorbed:
        latent_out=torch.einsum("bhqk,bkr->bhqr",p,c)
        out=torch.einsum("bhqr,hrv->bhqv",latent_out,uv)
    else:
        out=torch.einsum("bhqk,bhkv->bhqv",p,vv)
    return out.transpose(1,2).reshape(b,tq,-1) @ wo

Chunked Prefill（分块预填充）若先展开整段历史，会产生 [T, heads, dim] 中间张量。按序列和头分块处理 Load→Projection→Attention，可控制临时显存。投影数值过大则检查 Scale、饱和与累加精度；这是另一类问题。

5.5 GDN 与 KDA：如何遗忘、修正并读取状态

GDN（Gated DeltaNet，门控 Delta 网络）和KDA（Kimi Delta Attention，Kimi Delta 注意力）使用形状固定的矩阵保存历史信息。GDN 对整个 Head 的旧状态统一衰减；KDA 让 Key 的不同通道独立衰减。两者都用 Delta Rule（差值更新规则）写入当前 Token。

一、S 是什么？为什么 Delta 要先读再写？

以下固定单个 Head：k, q:[dₖ]，v:[dᵥ]，S:[dₖ,dᵥ]。S 是一张 Key→Value 的关联表。用 Key 读取旧预测 v̂ = Sᵀ k；用 Query 读当前输出 o = Sᵀ q。

如果直接向 S 加 k vᵀ，同一个 Key 多次写入会累积旧内容。Delta Rule 先读取当前记忆，再计算需要修正多少：

旧预测：v̂ = Sᵀ k　[dᵥ]
写入误差：e = v − v̂　[dᵥ]
Delta 更新：S′ = S + β · k eᵀ　[dₖ,dᵥ]
Delta Rule：沿当前 Key 方向纠正记忆
① 读取Sᵀk 得到旧预测 v̂
② 比较目标 v − 旧预测 v̂
③ 写入βk(v−v̂)ᵀ 加到 S
④ 输出新状态 S′ᵀq

β 是写入强度，范围通常为 0～1。若 Key 的二范数为 1，β=1 时对同一个 Key 重新读取会得到目标 v；β=0.5 表示向目标修正一半。真实 Key 之间可能相互干扰，因此模型需要学习合适的特征和门控。

二、GDN：先给整个 Head 的状态乘一个标量

衰减：S̄ₜ = αₜ Sₜ₋₁　（αₜ 为标量）
预测：v̂ₜ = S̄ₜᵀ kₜ
修正：Sₜ = S̄ₜ + βₜ kₜ (vₜ−v̂ₜ)ᵀ
输出：oₜ = Sₜᵀ qₜ

αₜ 越接近 1，旧状态保留越多；越接近 0，遗忘越快。将读取误差代入更新式，便得到论文中的合并写法：

GDN：Sₜ = αₜ (I − βₜ kₜ kₜᵀ) Sₜ₋₁ + βₜ kₜ vₜᵀ

这里 I 是 [dₖ,dₖ] 的单位矩阵；kₜkₜᵀ 是秩一矩阵，表示沿当前 Key 的方向修正。α 控制遗忘，β 控制当前 Key 的写入。

三、KDA：Key 通道分别决定遗忘多少

KDA 将 αₜ 改成长度为 dₖ 的向量。Diag(αₜ) 是由这些系数组成的对角矩阵，乘以 S 相当于按行缩放：S 的第 i 行乘以 αₜ,i。

衰减：S̄ₜ = Diag(α⃗ₜ) Sₜ₋₁　（α⃗ₜ:[dₖ]）
修正：Sₜ = S̄ₜ + βₜ kₜ (vₜ−S̄ₜᵀkₜ)ᵀ
输出：oₜ = Sₜᵀ qₜ
KDA：Sₜ = (I − βₜ kₜ kₜᵀ) Diag(α⃗ₜ) Sₜ₋₁ + βₜ kₜ vₜᵀ

与 GDN 相比，改变的是衰减粒度：一个 Head 不同 Key 特征可以具有不同的保留速度。β 仍是当前 Token、当前 Head 的写入强度标量。α⃗ 和 β 均从输入特征中学习得到。

四、用同一组数字完整计算

取 dₖ=2, dᵥ=1，旧状态 S=[2,10]ᵀ，k=[1,0]ᵀ，目标 v=6，读取用 q=[1,1]ᵀ，写入强度 β=0.5。我们只改变遗忘门控。

计算步骤GDN：α=0.8KDA：α⃗=[0.5,0.9]
衰减后的 S̄[1.6, 8]ᵀ[1, 9]ᵀ
用 k 读旧预测1.61
误差 e = 6 − v̂4.45
修正 β·k·e[2.2, 0]ᵀ[2.5, 0]ᵀ

五、Prefill 如何并行？Decode 要保存多少状态？

Decode 每产生一个 Token 执行一次上述更新，单层每个 Head 的状态大小为 dₖ×dᵥ，与历史 Token 数无关。Prefill 的递归依赖可通过 Chunkwise（分块并行）算法加速：块内将连续的状态转换重组为矩阵运算，块间传递最终状态。

KDA 的状态转换矩阵可展开成 DPLR（Diagonal-Plus-Low-Rank，对角加低秩）结构：

(I−βkkᵀ)Diag(α⃗) = Diag(α⃗) − β·k(k⊙α⃗)ᵀ

左边按 Token 递推，右边的“对角矩阵＋秩一修正”便于构造块内并行算法。实际高性能实现还涉及短卷积、门控参数化、数据布局和专用 Kernel。

PyTorch 参考代码：GDN / KDA 同一个 Step
import torch

def delta_step(S, k, v, q, alpha, beta):
    # S:[dk,dv] k,q:[dk] v:[dv]
    # GDN alpha:[]；KDA alpha:[dk]
    if alpha.ndim == 0:
        S_bar = alpha * S
    else:
        S_bar = alpha[:, None] * S
    v_hat = S_bar.T @ k        # [dv]
    error = v - v_hat          # [dv]
    S_new = S_bar + beta * torch.outer(k, error)
    output = S_new.T @ q       # [dv]
    return S_new, output

S = torch.tensor([[2.], [10.]])
k = torch.tensor([1., 0.])
v = torch.tensor([6.])
q = torch.tensor([1., 1.])
beta = torch.tensor(0.5)
print(delta_step(S,k,v,q,torch.tensor(0.8),beta))
print(delta_step(S,k,v,q,torch.tensor([0.5,0.9]),beta))

6.1 稳定 Softmax 与在线更新

稳定 Softmax 先减去行最大值 m，避免指数上溢：pᵢ=exp(xᵢ−m)/Σexp(xⱼ−m)。分块处理时，维护当前参考最大值 m、指数和 l，以及加权 V 的未归一化分子 U。新块最大值更大时，把旧统计量换到新尺度后继续累积。

m′ = max(m, max(S_block))　　α = exp(m−m′)
P_block = exp(S_block−m′)
l′ = αl + ΣP_block　　U′ = αU + P_block V_block
全部块完成后：O = U/l

递推让整行分数逐块消费。初始状态为 m=−∞、l=0、U=0；全掩码行单独定义输出，避免 −∞−(−∞) 产生 NaN。

PyTorch：稳定 Softmax、在线统计与 Attention 分块计算
import torch

def _work_dtype(x):
    return torch.float64 if x.dtype == torch.float64 else torch.float32

def safe_softmax(x: torch.Tensor, dim: int = -1) -> torch.Tensor:
    """Finite logits / -inf masks. Fully masked row returns zero by convention."""
    if not x.is_floating_point() or x.shape[dim] == 0:
        raise ValueError("Nonempty floating-point logits required")
    if torch.isnan(x).any() or torch.isposinf(x).any():
        raise ValueError("NaN / +inf logits are not supported")
    z = x.to(_work_dtype(x))
    m = z.amax(dim=dim, keepdim=True)
    anchor = torch.where(torch.isfinite(m), m, torch.zeros_like(m))
    e = torch.exp(z - anchor)
    den = e.sum(dim=dim, keepdim=True)
    p = e / den.clamp_min(torch.finfo(z.dtype).tiny)
    return p.to(x.dtype)

def online_attention(scores: torch.Tensor, values: torch.Tensor,
                     chunk: int = 3) -> torch.Tensor:
    """scores:[Tq,Tk], values:[Tk,Dv]. Scores may contain -inf masks.
    U is an UNNORMALIZED numerator; final result is U/l.
    """
    if scores.ndim != 2 or values.ndim != 2 or scores.shape[1] != values.shape[0]:
        raise ValueError("Invalid attention shapes")
    if chunk <= 0 or scores.shape[1] == 0:
        raise ValueError("Positive chunk and nonempty keys required")
    if torch.isnan(scores).any() or torch.isposinf(scores).any():
        raise ValueError("NaN / +inf scores unsupported")
    dtype = _work_dtype(scores)
    s, v = scores.to(dtype), values.to(dtype)
    m = torch.full((s.shape[0], 1), -torch.inf, device=s.device, dtype=dtype)
    l = torch.zeros_like(m)
    u = torch.zeros((s.shape[0], v.shape[1]), device=s.device, dtype=dtype)
    for j in range(0, s.shape[1], chunk):
        block = s[:, j:j+chunk]
        mn = torch.maximum(m, block.amax(-1, keepdim=True))
        anchor = torch.where(torch.isfinite(mn), mn, torch.zeros_like(mn))
        alpha = torch.exp(m - anchor)
        p = torch.exp(block - anchor)
        u = alpha * u + p @ v[j:j+chunk]
        l = alpha * l + p.sum(-1, keepdim=True)
        m = mn
    return (u / l.clamp_min(torch.finfo(dtype).tiny)).to(scores.dtype)

6.2 多分片输出与 LSE 归并

每个 KV 分片可独立计算局部输出 Oᵢ 和 LSE（Log-Sum-Exp，对数指数和） Lᵢ。局部输出按各自分母归一化，合并时用该分片在全局指数和中的占比加权。

L = logsumexp(L₀, L₁, …)
O = Σᵢ exp(Lᵢ−L) Oᵢ
全局指数和 = 8
O = (2/8)×2 + (6/8)×5 = 4.25

也可直接归并 (mᵢ,lᵢ,Uᵢ)：先取全局 m，再用 exp(mᵢ−m) 缩放各自 lᵢ/Uᵢ。每个 Query/Head 独立维护统计量；通信按最终输出的归属组织。

6.3 FlashAttention 1—4

FlashAttention将 Q/K/V 分块，结合在线 Softmax，在片上消费局部分数，减少 Tq×Tk 中间矩阵写入 HBM。后续版本继续优化线程分工和硬件流水。

版本主要优化对象实现要点
FA1中间分数的 HBM 读写Tiling（分块）与在线 Softmax；逐块累积 O

FA3Hopper 异步硬件TMA、WGMMA 与职责分离，交叠搬运、QK/PV 和 Softmax
FA4Blackwell 的片上与非矩阵瓶颈前向优化 exp/重缩放；反向利用 TMEM、2-CTA 等降低部分片上流量

当新块最大值与当前参考值差距较小时，可继续沿用旧参考 m，把新块分子、分母也记在这个尺度；达到触发条件后统一重缩放。保持尺度一致和足够数值裕量，是最终正确归一化的前提。

exp 所用的特殊函数管线可能限制吞吐。FA4 把部分指数计算分配给基于 FMA（乘加）的多项式近似，与硬件指数指令分担工作。阈值、exp/exp2 单位和近似精度按实现配置；数值验收同时看误差与任务质量。

6.4 Flash-Decoding：把长 KV 分给更多 CTA

短 Q、小 Batch 时，按 Batch×Head 分配 CTA 可能提供不了足够并行工作。Flash-Decoding再沿 KV 序列切块，各 CTA 独立计算局部统计，最后按上一节的公式归并。

Flash-Decoding：并行读不同 KV 区间
Q：一个 TokenQuery 长度≈1，单头 CTA 数可能不足
切 KV历史 128K 拆成多个 KV Chunk
并行不同 CTA 分别算局部 Softmax 统计
合并局部 max / sum / numerator 精确归并

与 FlashAttention 减少 N² 中间 IO 的动机不同：Flash-Decoding 主要解决短 Q 下的 GPU 并行度不足。

分块数增加带来更多并行，也增加中间结果、归并与启动成本。长 KV、小 Batch 更容易获益；Batch×Head 已提供充分并行或 KV 很短时，可减少拆分。Flash-Decoding 优化一次 Attention，推测解码则提高一次目标模型验证产生的 Token 数。

推理框架把长度不断变化的请求组织成可执行批次，同时管理 KV、排队和数据搬运。先看一个请求的状态，再扩展到并发和多实例。

7.1 KV 状态与前缀复用

KV Cache保存当前模型已计算的历史 K/V 或 latent；Prefix Cache（前缀缓存）为可共享的前缀状态建立索引。前者减少当前请求的历史重算，后者让后续请求复用公共前缀。

缓存数据与前缀索引的关系
KV Cache保存已经计算的 Key/Value 或 MLA latent
Prefix Cache为历史 token blocks 建索引、标记可复用
请求进入Prefix Hash + 模型/模板/租户元数据校验
命中Reuse blocks，只计算新增后缀

块键由父前缀标识、当前块 Token 和计算身份构成。身份包括权重/适配器、位置编码、缓存格式及租户隔离域等。命中后增加引用，尚在使用的块受回收保护。公共前缀命中比例、实际免算 Token 比例和最终恢复成功率分别统计。

前缀块哈希链：把块和完整前缀绑定
# 理解索引逻辑的伪代码
parent_hash = None
for block in prompt_blocks:
    key = hash((parent_hash, tuple(block.token_ids),
                model_version, template_version, kv_abi, tenant_salt))
    if key not in prefix_index: break
    matched.append(prefix_index[key]); parent_hash = key
# 命中的 block 仍须确认引用/容量、不能在使用期间被回收

连续多轮对话通常只新增后缀。路由兼顾前缀亲和与负载，长时间 Tool Wait（工具等待）可触发保留、下沉或回收；恢复选择同时考虑剩余时限和重算成本。

7.2 Paged KV：按块分配、共享与回收

请求的输出长度事先未知。按最大长度预留连续空间会占用大量暂时闲置的显存。Paged KV（分页 KV）把缓存分成固定 Token 数的块，随序列增长按需申请，用 Block Table（块映射表）记录逻辑顺序。

通过块表寻址
logical_block, offset = divmod(token_pos, block_size)
physical_block = block_table[request_id, logical_block]
address = kv_base + physical_block * block_stride + offset * token_stride
# 完整寻址还包括 layer / head / dtype 对应的布局偏移

完整的只读前缀块可以被多个请求引用。共享尾块发生分叉写入时，Copy-on-Write（写时复制）先建立私有副本再写。请求结束后减少引用，异步读写都完成后再回收。块越小，尾部浪费越少，块表和寻址开销越多。

7.3 连续批处理与 Chunked Prefill

Continuous Batching（连续批处理）在迭代边界加入新请求、移出已完成请求。调度预算通常同时考虑本轮 Token 数和可用 KV 页，避免长请求占据整个批次。

Chunked Prefill把长输入拆成较小块，与 Decode 更细粒度交错。较小块改善响应公平性并降低临时激活峰值；较大块更容易利用矩阵计算吞吐。调参同时看排队、TTFT、ITL、工作区与 HBM。

一次调度迭代的预算逻辑
budget = max_tokens_per_step
for request in select_ready_requests():
    n = choose_chunk(request, budget)
    if kv_pool.can_reserve(request, n):
        schedule(request, n)
        budget -= n
# 执行后提交已完成 Token；取消/结束请求随后回收其引用。

7.4 三类 Chunk：调度分块、Attention 分块、状态分块

“Chunked”描述的是把工作拆成多个块。推理系统里有三种常见的分块对象：待处理 Token、历史 K/V、递归状态更新。它们可以在同一套模型中同时出现。

② 的合并公式：若每个 KV 分片返回局部归一化输出 Oᵢ 和对数归一化量 LSEᵢ，则

m = maxᵢ LSEᵢ
O = [Σᵢ exp(LSEᵢ−m) · Oᵢ] / [Σᵢ exp(LSEᵢ−m)]

例如两段 KV 的 LSE 分别为 2 和 3，第二段对最终输出的权重更大。归并时保留每段的归一化质量，结果等价于对全部 KV 一起做 Softmax。Online Softmax 在一个 Kernel 内逐块维护统计量；跨 CTA/Rank 时可以用 LSE 归并局部结果。

可执行代码：合并多个 KV 分片的 Attention 输出
import torch

def merge_attention(partial_o, lse):
    # partial_o:[parts, d_v]，每段已经归一化
    # lse:[parts]，每段的 logsumexp(scores)
    weight = torch.softmax(lse, dim=0)  # 数值稳定的分片权重
    return (weight[:, None] * partial_o).sum(dim=0)

# 多 Query/Head 时，对每个 Query/Head 独立执行相同归并。

面试联系：Serving Chunk 主要影响 TTFT、ITL 和调度公平性；Attention KV Tiling 主要影响临时激活、并行度和 IO；KDA Chunkwise 主要解决递归计算的 Prefill 并行化。

7.5 CUDA Graph 与动态 Shape

CUDA Graph（CUDA 图）捕获一组设备工作及依赖，重放时降低 CPU 逐 Kernel 提交开销。推理常按 Batch/Token 形状分桶，给输入和工作区提供稳定地址；每轮把新数据填入缓冲后重放。

问题工程处理
动态 Batch选择图桶并填充空位，记录有效 Token 与填充比例
动态 KV用稳定地址的块表/元数据缓冲描述变化；后端需支持这种访问
资源成本图和内存池占用计入 HBM 账本
回退记录捕获、重放与 eager 路径的比例，定位 Shape 未命中的原因

torch.compile优化图捕获、融合和代码生成；CUDA Graph 优化重复提交，两者可组合。首次编译和捕获单列为启动成本，稳定运行阶段再比较性能。

7.6 P/D 分离与容量规划

P/D Disaggregation（预填充／解码分离）让计算密集的 Prefill 和延迟敏感的 Decode 使用独立资源池。收益来自资源配置、调度隔离和独立扩容，新增成本主要是 KV 迁移、安装与跨池协调。

Agent 请求若已有很长前缀驻留在 D，少量后缀在本地处理可能更便宜；分离部署可通过前缀亲和、增量传输和池间复用减少移动。比较同一服务目标下的总关键路径。

P 需求 ≈ λ × E[实际需 Prefill 的 Token]
D 需求 ≈ λ × E[输出 Token]
实例数 ≈ ceil(需求 / [该负载下实测容量 × 目标利用比例])

算例：100 请求/s，输入均值 2000、有效免算比例 40%、输出均值 500；P 需求 12 万 Token/s，D 为 5 万。若单 P/D 容量分别为 6 万/1.2 万，取 70% 目标利用比例，初估需 3P、6D。继续检查 KV 容量、传输和尾延迟。

7.7 KV 生命周期、恢复与长输出均衡

容量治理从减少每 Token 字节、共享前缀、冷热分层和调度准入四处着手。正在消费的 KV 保持有效引用；闲置状态根据再访问概率、重算成本和剩余容量选择保留、下沉或淘汰。

T_restore = 查找 + 排队 + 传输 + 安装 + 必要同步（重叠段按关键路径计）
选择条件：预计恢复成本 < 重算成本，且满足剩余时限与资源预算

长输出会让请求在 D 上停留更久并持续增长 KV。路由可用活跃 Token、历史长度、预计剩余时长和 KV 占用估负载；迁移只在节省的等待超过搬运成本时采用。预留容量、长度分桶、请求老化和租户配额共同控制尾延迟。

恢复的正确性与失败处理

固定权重版本、缓存格式、逻辑前缀和分片身份；读入后校验成员完整性，建立设备可消费依赖，再统一准入。对象缺失或不兼容时回源/重算。元数据可见、字节搬完、设备可读和请求成功是四个不同观察点。

08　推测解码与优化组合

推测解码用便宜的候选生成，换取目标模型一次验证多个位置。收益取决于每轮有效产出与完整服务成本。

8.1 Draft、Verify 与接受长度

Draft（草稿生成）提出候选 Token，Target（目标模型）并行计算这些位置的条件分布，再进行接受/拒绝。保留通过的前缀，并从首个拒绝处修正；后续候选对应的上下文随之失效。

S ≈ Tbaseline/token × E[Nemitted] / E[Tcycle]
T_cycle：草稿、验证、接受处理与调度的整轮关键路径

统计实际新输出 Nemitted，包括接受前缀和纠正/bonus Token，遇 EOS 或长度限制时截断。MTP（多 Token 预测）常用模型附带的预测模块生成候选，系统中再接目标验证。

低并发长输出中，批量验证可提升目标计算的有效产出；高并发时连续批处理已提高利用率，新增草稿和验证会争用 Token/KV/计算预算。按并发、长度与负载选择深度。

8.2 拒绝采样与 KV 回退

在同一已接受上下文上，草稿从 q 采样 x，目标分布为 p；两者包含实际温度与截断规则。Rejection Sampling（拒绝采样）用下面的概率保留候选：

a(x) = min(1, p(x)/q(x))
拒绝后的修正分布：r(x) = max(p(x)−q(x),0) / Σᵥ max(p(v)−q(v),0)

接受部分贡献 min(p,q)，拒绝后的修正部分补回 p 超过 q 的概率质量，合计得到目标分布。贪心模式按目标 Top-1 验证。实现时推进已接受长度，释放或复用被拒后缀的 KV 槽，并正确保留纠正 Token 的后续计算状态。

多候选结构与概率保证

上述式子对应逐位置、同一条件上下文下的候选分布。树形、并行草稿和不同 tokenizer 的方案需按其真实提议分布与验证协议实现。保分布是概率语义；同一随机种子在不同采样执行路径上可以产生不同序列。

8.3 EAGLE-3、DFlash 与 DSpark

目标模型的 Hidden State（隐藏状态）已经编码上下文，可为草稿提供比 Token ID 更丰富的特征。比较方法时同时看特征融合成本、块内依赖、草稿耗时和目标验证浪费。

方法候选生成需要比较的成本
EAGLE-3多层目标特征融合，草稿自回归推进多步草稿延迟与接受长度
DFlash目标特征条件下，块扩散草稿一次并行生成并行生成成本与块后部接受衰减
DSpark并行骨干＋轻量顺序 Markov head；置信度调度恢复块内依赖的开销与负载感知验证长度

8.4 动态深度、TTFT 与高并发

第 i 个候选只有在前 i−1 个候选都接受时才增加有效前缀。动态深度按前缀存活概率和引擎成本曲线分配验证预算，负载高时减少低价值后缀。

8.5 优化组合与 2×2 消融

组合互补来源额外成本或重叠
MTP＋连续批处理中低负载时增加验证矩阵规模高负载争用 Token/KV 预算
MTP＋CUDA Graph减少草稿与验证的提交开销动态深度、图桶填充、图内存池

固定一项度量和负载，测四组：T₀、T_A、T_B、T_AB。以延迟的加法模型为基准，组合预期为 T_A+T_B−T₀：

I = T_AB − T_A − T_B + T₀
I<0：相对加法预期的正协同；I≈0：近似独立；I>0：重叠或相互干扰

算例：100、80、70、45 ms，I=−5 ms；组合比加法预期的 50 ms 更好。另看 T_AB 是否优于两个单项。用重复实验区间判断差异，吞吐或乘法加速比需使用相应的交互模型。

延迟消融计算器 · 单位 ms
示例：加法预期 50 ms，交互项 −5 ms；组合优于两个单项。

MTP＋Graph 变慢时，依次看时间线中的提交/验证、图桶与回退、无效验证 Token、KV/图池导致的 Batch 收缩。保持质量门槛和开放式到达负载，才能比较服务收益。

09　量化与数值精度

量化改变表示、搬运和计算路径。选型同时检查数值误差、缩放粒度、原生指令和目标形状下的有效速度。

权重、激活与 KV 量化FP8、MXFP8 与 FP4 格式AWQ、SmoothQuant 与精度分配浮点误差、原子加与可复现性

9.1 权重、激活与 KV 量化

W4A16 表示 4-bit 权重与 16-bit 激活，常以解包/反量化配合矩阵计算；W8A8 FP8 使用 FP8 权重与激活，可进入相应 Tensor Core 路径；FP8 KV 主要减少历史状态容量与读取/传输字节。存储精度、计算输入精度、累加精度分别记录。

对称整数量化：q = clip(round(x/s), q_min, q_max)　　x̂ = s·q
非对称量化：q = clip(round(x/s)+z, q_min, q_max)　　x̂ = s·(q−z)

Scale（缩放因子）覆盖的范围决定离群值对其他数值的影响。Per-tensor、Per-channel、Per-head 和 Block-wise 分别按张量、通道、头或数据块分组；粒度与布局共同决定元数据和内核成本。

9.2 FP8、MXFP8 与 FP4 格式

格式表示与缩放常见取舍
FP8 E4M34 位指数、3 位尾数（另有符号位）较高精度、较窄范围
FP8 E5M25 位指数、2 位尾数更宽范围、较低精度
MXFP832 个连续值共享 E8M0 幂次 Scale硬件块缩放；量化方向影响分组
MXFP4E2M1 数据，32 值一组 E8M0 Scale数据更紧凑，范围与质量更敏感
NVFP4E2M1 数据，16 值一组 E4M3 Scale，加张量级缩放更细块与不同 Scale 表达

普通 Block-wise FP8 是一类方法，块可取 1×128、128×128 等；MXFP8 有明确的块与 Scale 格式。转置后沿新方向的 32 值分组不同，通常从高精度原值重新量化对应方向。预排布 Scale 或融合量化，可减少额外转换内核。

9.3 AWQ、SmoothQuant 与精度分配

AWQ（激活感知权重量化）利用激活统计选择缩放，保护对输出更敏感的权重通道；SmoothQuant通过等价缩放把激活离群值的难度转移给权重，便于低精度 W×A。GPTQ使用近似二阶信息对逐步量化误差进行补偿。

模块主要关注
QKV/输出投影、Expert GEMM低精度矩阵吞吐、Scale 和解包开销
QK/PV 与 KV长上下文误差、K/V 分布差异、位置分量
Softmax/Norm归约和指数的内部累加精度；输入输出 dtype 可另选
MoE RouterTop-K 排序接近时，小误差可能改变专家选择
SwiGLU gate_proj属于 MLP 线性投影，按其数值与内核路径评估

W4 的权重更小，FP8 的矩阵指令可能更快；比较还取决于 Batch、Shape、反量化和缓存。较高质量的量化先通过任务门槛，再报告可缓存 Token、吞吐和单位成功请求成本。

9.4 浮点误差、原子加与可复现性

FP32 有 24 位有效二进制精度（含隐藏位）。数值越大，相邻可表示值的间距 ULP（末位单位）越大。并行求和改变累加顺序，就会改变中间舍入。

FP32 大数减小数：观察舍入与 ULP
import numpy as np
x = np.float32(9.9e9)
y = np.float32(1e-9)
print(int(x))       # 9900000256
print(np.spacing(x))# 1024.0
print(x - y == x)   # True

例中 9.9×10⁹ 转为 FP32 后是 9,900,000,256，ULP=1024；减去 10⁻⁹ 后仍舍入到该值。AtomicAdd 保证每次更新原子完成，多线程到达顺序可能变化；固定树形归约有助于控制次序。验收根据任务选择绝对/相对误差、逐位一致或下游质量指标。

量化与 MTP 组合时，分别测 BF16/FP8 × 开/关 MTP 四组。数值变化影响 Hidden State 和分布，也会改变接受长度；结果分布的验证基准是实际使用的 Target。

10.1 DP、TP、PP、CP 与 EP

并行轴切分对象典型通信与成本

Column Parallel Linear（列并行线性层）按输出维切权重，生成局部输出；Row Parallel Linear（行并行线性层）按输入维切分，局部乘积需要归约。配对使用可减少中间收集。MoE 中 Attention 的 DP/TP 与 Expert 的 EP 可以复用同一批 rank，资源数量按实际通信组推导。

10.2 TP=2：两次 Linear 为什么只需一次归约？

以输入 X:[tokens,H]、FFN 中间维度 4H 为例。第一层按输出通道切成两份（Column Parallel）；第二层按输入通道切成两份（Row Parallel）。每张卡先完成自己的两次矩阵乘，最后把局部输出相加。

FFN(X) = Σᵢ [ act(XW₁,ᵢ) W₂,ᵢ ]
W₁:[H,4H] 按列切；W₂:[4H,H] 按行切

为什么可以省去第一层后的 AllGather？因为逐元素激活函数对各自的通道独立计算，第二层又恰好消费同一份中间通道。各卡保留局部中间张量，直到输出维度需要相加时再通信。SwiGLU 等门控 FFN 还要把 Gate 与 Up 投影按对应通道配对切分。

NumPy 手算：TP=2 与完整 FFN 输出一致
import numpy as np
rng = np.random.default_rng(0)
x = rng.normal(size=(3, 8))
w1 = rng.normal(size=(8, 32))
w2 = rng.normal(size=(32, 8))
act = lambda z: np.maximum(z, 0)
ref = act(x @ w1) @ w2
w1_parts = np.split(w1, 2, axis=1)  # 输出通道切分
w2_parts = np.split(w2, 2, axis=0)  # 输入通道切分
partial = [act(x @ a) @ b for a, b in zip(w1_parts, w2_parts)]
out = partial[0] + partial[1]      # 模拟 AllReduce sum
np.testing.assert_allclose(ref, out, rtol=1e-12, atol=1e-12)

通信位置：Column Parallel 生成局部特征；Row Parallel 生成需要求和的局部贡献。启用 Sequence Parallel（序列并行）时，部分前向归约可变为 ReduceScatter，下一层再 AllGather 输入；通信原语由输出的分布方式决定。

10.3 集合通信与字节账本

原语结果归属
Broadcast（广播）根 rank 的数据复制给组内全部 rank
AllGather（全收集）各 rank 的分片拼接，所有 rank 获得完整结果
ReduceScatter（归约散发）对应元素归约后，每 rank 只保存一个结果分片
AllReduce（全归约）所有 rank 获得归约后的完整结果
All-to-All（全互换）每个 rank 向各目标发送不同数据，用于重新分布
Ring AllGather：每 rank 原有 S 字节，最终输出 PS
每 rank 发送量 = 接收量 = (P−1)S
Ring AllReduce：每 rank 输入 D 字节，每 rank 发送量 ≈ 2(P−1)D/P

算例：8 rank，每片 256 MiB，AllGather 输出 2 GiB。独立分配输出时，输入+输出为 2.25 GiB；每 rank 发送/接收各 1.75 GiB。workspace 和在途缓冲另外计入。通信耗时可从轮次数×启动延迟加数据量/有效带宽估算。

10.4 Ulysses、Ring 与 DCP

Ulysses Sequence Parallel（序列并行）用 All-to-All 把序列分片换成头分片，每 rank 计算相应头的全序列 Attention，再换回。Ring Attention（环形注意力）保留本地 Q，轮流接收 K/V 分片并更新在线归一化统计。

Decode 的 Q 短、历史 KV 长，常选择把 Q 送到 KV owner：各 rank 读本地历史，返回局部 O/LSE，再加权归并。长 Q 的 Prefill 则结合网络、头数、KV 布局和重叠空间选择 Pass-Q 或 Pass-KV。

比较对象：传 Q 的字节 + O/LSE 归并成本
对比：传 KV 的字节 + 分块计算/重叠成本
PCP、DCP 与模型版本

框架中 PCP/DCP 的组定义与缓存归属分别查配置。例如 vLLM v0.27.1 的 PCP 扩大并行 Prefill 进程规模，而 KV shard count 另由对应规则决定；DCP 可复用 TP ranks。选择方案时记录固定版本、头数/latent 维度和布局。

10.5 通信计算重叠与 Flux

Overlap（重叠执行）用独立计算覆盖通信时间。双 CUDA Stream 提供并发提交渠道，数据依赖决定哪些工作可提前执行，SM、HBM 和网络竞争决定可兑现的收益。

Flux等细粒度方案把 Tile 的数据就绪与 GEMM 调度关联：一部分输入到达即可启动对应计算，或在输出尾处理阶段推进归约。重点是缩小依赖粒度和传递完成信号。验证时看暴露通信时间、重叠后的矩阵速度和总关键路径。

10.6 MoE 执行、通信量与负载均衡

MoE（混合专家模型）由 Router（路由器）为每个 Token 选择 Top-K 专家及权重。按目标专家整理 Token，Dispatch（分发）到对应 rank，执行专家 MLP，再 Combine（合并）回原 Token 并按路由权重组合。

均匀路由下：每 expert 平均 Token 数 = B_global × K / E
每源 rank 的远端 Dispatch payload ≈ B_local × K × H × b × f_remote

式中 E 是专家数、H 是隐藏维度、b 是元素字节、f_remote 是远端比例。Combine 另按输出精度统计；目标 rank 内去重、共享专家、Scale、索引和对齐会改变实际流量。

算例：固定每 rank 16 Token、E=256、K=8，EP 组为 P 个 rank，则每 expert 均值为 P/2：P=8/32/64 对应 4/16/32 Token。这里总 Batch 随 P 增长；固定全局 Batch 时，EP 单独增加不会增加该均值。

负载不均来自路由偏斜、局部小批量和长尾专家。训练侧可用均衡损失或容量约束；推理侧可用专家放置/副本、路由感知调度和更细 Tile。副本增加权重存储与同步，效果同时看最慢 rank 和通信。

10.7 DeepEP 与 Grouped GEMM

DeepEP提供 MoE Dispatch/Combine 通信内核。吞吐路径重视批量搬运、目标 rank 内复用和拓扑；低延迟路径重视少同步、小批量和设备端执行。历史 Normal/Low-latency 设计与新接口分开理解，当前 V2.5 将相关能力统一到 EPBuffer。

Grouped GEMM（分组矩阵乘）把多个专家的不同 M 合并调度；N/K 通常相同。Contiguous（紧凑布局）拼接各专家行段并附边界；Masked（掩码布局）预留容量，由设备侧有效计数控制计算，便于动态 Token 数与 CUDA Graph 配合。

调度先根据各专家的有效行数计算 Tile 数和前缀和，再把全局 Tile ID 映射为 expert、行块、列块。按 M 对齐产生的填充、Scale 排布、L2 复用和尾部 Tile 都计入成本。大 EP 的选型同时考虑每专家批量、权重容量、跨节点 A2A 和最慢专家。

11.3 AdamW、归一化与混合精度

RMSNorm(x) = γ·x/√(mean(x²)+ε)

归一化中的归约通常使用较高内部精度。梯度裁剪作用于更新前的梯度，数值溢出、数据错误和学习率问题仍按各自原因处理。Pre-Norm/Post-Norm 表示归一化与残差分支的相对位置。

12　Agentic RL 与异步 Rollout

在强化学习目标的基础上，Agentic RL 需要把模型动作、工具观察、奖励、采样策略与执行状态组织成可持续交付的轨迹。

SFT、PPO、GRPO 与概率身份工具执行与性能瓶颈异步 Rollout 与状态恢复

12.1 SFT、PPO、GRPO 与概率身份

SFT（监督微调）学习给定标签序列；PPO（近端策略优化）使用采样奖励和受约束的概率比更新策略；典型 GRPO（组相对策略优化）用同一提示下多条回答的相对奖励估计优势，省去同类 Critic（价值网络）路径。

典型组优势 Aᵢ = (rᵢ − mean(r_group)) / (std(r_group)+ε)
概率比 ρ = exp(logπ_current(a|s) − logπ_behavior(a|s))
PPO 代理目标包含 min(ρA, clip(ρ,1−ε,1+ε)A)

Behavior Policy（行为策略）实际生成样本；冻结的 Old Policy（旧策略）用于算法定义的比值；Reference Policy（参考策略）常用于 KL 约束。记录动作、上下文、掩码、版本与约定的采样概率，温度/top-p 造成的分布变换也要与训练目标一致。

组内奖励相同会使典型相对优势接近零，其他损失项仍可能有梯度。RL 评测同时看任务成功、数据覆盖、奖励投机、成本和失败样本。

12.2 Agentic RL 的状态与性能瓶颈

Agentic RL（智能体强化学习）的轨迹交替包含模型动作与工具/环境观察。动作 Token 参与约定的策略目标，观察 Token 作为后续条件，通过 Action Mask（动作掩码）区分。Skill（技能封装）提供可复用步骤、工具与规则；RSI（递归自我改进）指用评测反馈改进能力的循环，具体语义应与讨论的系统对齐。

Rollout（采样轨迹生成）可以与训练交错。轨迹保留采样策略、真实 Token、动作掩码、行为概率、工具结果及组关系；KV 是可重建的加速状态，兼容性由权重、布局和引擎共同决定。

13　C++、操作系统与并发

从地址空间、执行单元到对象生命周期，理解“谁拥有数据、谁能修改、什么时候可以回收”。这些基础贯穿 GPU、网络和存储。

进程、线程与协程虚拟内存、缺页与 mmap内存放置与缓存行竞争原子操作与发布顺序锁、CAS、引用计数与 RCUC++ 指针、拷贝与对象模型

13.1 进程、线程与协程

进程提供地址空间和资源隔离；同进程线程共享内存，由操作系统调度；协程由运行时在挂起点切换。并发描述交错推进，并行描述同时使用多个执行资源。I/O 密集服务可用事件循环组织大量等待，CPU 重计算交给合适的线程、进程或设备。

启用 GIL（全局解释器锁）的 CPython 中，纯 Python 计算线程通常竞争解释器锁；I/O 和释放 GIL 的原生库可并发推进，free-threaded 构建另有实现。阻塞调用或长时间计算会占住协程事件循环。

单核上多线程可能在一个线程等待 I/O 或内存时推进另一个工作；纯计算且已充分利用执行资源时，新增线程主要增加切换与竞争。SMT（同时多线程）的收益也取决于可利用的执行空隙。

13.2 虚拟内存、缺页与 mmap

程序访问虚拟地址，页表映射到物理页，TLB（地址转换缓存）缓存近期映射。mmap（内存映射）建立文件与虚拟地址的关联，访问时按需建立映射和调入数据。

Page Cache（页缓存）存放文件数据。映射可减少传统 read 路径的用户态复制，首次访问仍可能付出缺页与存储成本。MAP_SHARED 共享修改，MAP_PRIVATE 写入采用私有语义；文件截短后继续访问原映射可能触发错误。

13.3 内存放置与缓存行竞争

机制主要作用调优条件
Pinned Memory（页锁定内存）提供稳定 DMA 页，便于异步拷贝限制池大小；等传输完成再复用
NUMA将线程、内存和设备放在较近拓扑域绑核与 first-touch（首次触碰分配）配合
Huge Page（大页）减少 TLB 条目与页表开销关注分配、碎片和工作集
Unified Memory运行时管理 CPU/GPU 访问与迁移观察缺页、驻留和预取
缓存行隔离减少不同变量之间的伪共享先定位热写字段，再用分片/对齐控制工作集

伪共享发生在不同线程写同一缓存行中的不同变量。先用每线程局部统计再归并，常能减少一致性流量；过度 Padding 会增加工作集。数量级见 2.4 存储容量与延迟。

13.4 原子操作与发布顺序

atomic（原子操作）控制相应对象的原子读改写；mutex（互斥锁）组织临界区；内存顺序建立普通数据的跨线程可见性。生产者先写 payload，再 release-store 标志；消费者 acquire-load 读到该发布值后，可安全读取此前写入。

C++17：release/acquire 单次发布
// Single publication demo. Data is immutable after publication.
#include <atomic>
#include <cassert>
#include <string>
#include <thread>
int main() {
    std::string payload;
    std::atomic<bool> ready{false};
    std::thread producer([&] {
        payload = "complete-data";
        ready.store(true, std::memory_order_release);
    });
    std::thread consumer([&] {
        while (!ready.load(std::memory_order_acquire)) {
            std::this_thread::yield();
        }
        assert(payload == "complete-data");
    });
    producer.join();
    consumer.join();
}

relaxed只提供相应原子对象的原子性；C++ volatile用于特殊访问语义，不承担线程间同步。CPU 原子协议、CUDA 事件与 RDMA 完成协议分别在各自的内存与执行模型下使用。

13.5 锁、CAS、引用计数与 RCU

短临界区、等待时间可预测时可考虑自旋；等待较长时互斥锁让线程睡眠。Lock-free（无锁）保证系统整体进展，Wait-free（无等待）进一步要求单次操作步数有界。高争用的 CAS 重试仍会消耗带宽与 CPU。

CAS（比较并交换）只比较当前值；地址经历 A→B→A 会造成 ABA。版本标签识别代际变化，Hazard Pointer（危险指针）或 Epoch（代际回收）保护仍被读取的对象。

引用计数保护所有权生命周期，数据内部并发读写另需协议。RCU（读、复制、更新）先发布新指针，等待旧读者宽限期结束后回收旧对象。交给异步 GPU/NIC 的缓冲区也要保留到实际消费完成，再归还内存池。

13.6 C++ 指针、拷贝与对象模型

const 限定的是指针还是所指对象
const int* A;  // A 指向 const int；允许 A 改指向，不允许通过 A 改值
int const* B;  // 完全相同的类型
int* const C = some_ptr; // 指针 C 自身不能重新赋值，所指值可改
const int* const D = &x; // 指针和所指值都不能通过 D 修改
交换两个指针的指向
const int one=1, two=2;
const int* A=&one; const int* B=&two;
std::swap(A, B);  // A→2, B→1；常量原值没被改动

RAII（资源获取即初始化）把资源释放绑定到对象析构。拥有堆内存的类型需要定义复制后的所有权：浅拷贝共享地址，深拷贝复制内容。优先由标准容器与智能指针管理资源，手写类时同时考虑复制、移动和析构。

深拷贝与移动：复制后对象独立；赋值使用 copy-and-swap
#include <algorithm>
#include <cstddef>
#include <memory>
#include <utility>

class Buffer {
    std::size_t n_ = 0;
    std::unique_ptr<int[]> data_;
public:
    explicit Buffer(std::size_t n = 0)
        : n_(n), data_(n ? std::make_unique<int[]>(n) : nullptr) {}
    Buffer(const Buffer& other) : Buffer(other.n_) {
        if (n_) std::copy_n(other.data_.get(), n_, data_.get());
    }
    Buffer(Buffer&& other) noexcept
        : n_(std::exchange(other.n_, 0)), data_(std::move(other.data_)) {}
    void swap(Buffer& other) noexcept {
        std::swap(n_, other.n_); data_.swap(other.data_);
    }
    Buffer& operator=(Buffer other) noexcept { swap(other); return *this; }
    int& operator[](std::size_t i) { return data_[i]; }
    const int& operator[](std::size_t i) const { return data_[i]; }
    std::size_t size() const noexcept { return n_; }
};

常见 C++ ABI 用虚表指针实现动态派发。sizeof取决于成员、基类子对象、虚继承、对齐与填充，虚函数代码本身不逐份存进对象。空类也需可区分地址；多继承可能有多个虚表指针。给定编译器/ABI 后再画布局。

交换两个 int 时 std::swap通常最清楚。异或三步要求 a/b 是不同对象；加减三步还需处理有符号溢出的未定义行为。

14　网络、RDMA 与排队

网络传输完成后，应用还要确认数据可见、业务生效和资源可回收。高负载时，队列与重试会直接改变尾延迟。

14.1 TCP、RPC 与 I/O 通知

TCP 提供连接内有序字节流。RPC（远程过程调用）还定义消息长度、请求 ID、版本、错误与结果语义。服务端已提交业务但响应丢失时，客户端要通过幂等键重试或查询结果。

阻塞描述调用是否等待，异步描述完成如何通知。epoll报告 I/O 就绪；非阻塞读写仍要处理短读、短写和 EAGAIN。边沿触发通常持续消费到 EAGAIN，水平触发在就绪状态持续时重复通知。解析、磁盘缺页或其他阻塞调用仍可能拖住事件循环。

14.2 RDMA 对象与完成语义

RDMA（远程直接内存访问）让设备访问获授权的远端内存。MR（注册内存区域）指定地址范围与权限，QP（队列对）承载工作请求，CQ（完成队列）报告完成与错误。Send/Recv 需要双方收发配合，Read/Write 操作远端授权地址。

单边操作减少远端 CPU 对每次数据搬运的参与，连接、注册、权限和生命周期仍由协议管理。普通 Write 后如何通知远端应用、不同 QP 的顺序、注销 MR 前等待哪些工作，都按传输类型与 API 约定执行。

GPUDirect RDMA在支持的拓扑上让 NIC（网卡）与 GPU 内存直接交换数据，省掉 Host Staging（主机中转）。消费者还需平台支持的可见性与流依赖。小消息延迟、注册、PCIe/NUMA 位置和同步成本共同决定收益。

14.3 带宽时延积与 Little 定律

T_transfer ≳ 启动延迟 + Bytes / 有效带宽
BDP（带宽时延积）= 链路带宽 × RTT
Little 定律：L = λW（稳定系统的平均在途量）

算例：200 Gbit/s=25 GB/s，RTT=20 μs，BDP 约 500 KB；要持续利用链路，需要足够在途数据。服务完成率 1000 请求/s、平均停留 50 ms，对应平均在途请求 50。QPS、并发数和线程数描述不同量。

GB 与 GiB、bit/s 与 Byte/s 分别统一单位。Little 定律用平均值；尾延迟另从排队、服务时长分布和扇出分析。

14.4 截止时间、重试与背压

Deadline（截止时间）从入口向下游传递剩余预算。可重试错误使用有限次数、退避和随机抖动；由一层统筹重试，避免多层放大。限流控制容量，熔断在持续异常时快速失败，取消请求触发清理流程。

Backpressure（背压）把下游承载限制反馈给上游。队列同时限制请求数、字节、Token 或预计成本；过期任务退出，低优先级通过老化避免长期饥饿。取消后，仍在使用的 DMA/GPU 缓冲等完成再释放。

14.5 扇出、慢节点与尾延迟

等待所有分片返回时，总延迟受最慢一路影响。独立同分布的教学模型中，单路在 t 内完成的概率为 F(t)，n 路全部完成的概率为 F(t)n；F=0.99、n=100 时仅约 36.6%。

Hedged Request（延迟对冲）在慢请求达到阈值后发到另一副本，以额外负载换尾延迟；需要幂等、取消和额度限制。观测按请求合并延迟分布，保留超时和失败；全局 P99 由原始分布计算。开放式到达压测持续施加既定到达率，更容易暴露排队。

15.5 WAL、fsync、MVCC 与旧版回收

WAL（预写日志）让恢复所需记录先满足持久性要求，再安全推进相关数据更新。write可能只进入操作系统缓存，语言库 flush 只完成其缓冲刷新，fsync用于请求持久化文件状态；新建/重命名文件的目录项持久性还需相应目录操作。

MVCC（多版本并发控制）让读者固定一个可见快照，写者创建新版本。旧版本需在活跃读者、复制、恢复和保留策略都允许后回收。Tombstone（删除标记）保留到足以遮蔽所有可能出现的旧值，避免合并或副本追赶时旧数据重新可见。

成本来源

写放大日志、刷盘、合并及副本重写

15.6 缓存一致性、准入与副本

Cache Aside（旁路缓存）在未命中时读主存储并回填，写路径更新主存储后使缓存失效。并发读可能拿着旧值晚到回填，因此用版本、失效序号或协调协议约束可见性。

16.1 一致性模型与 Raft

保证定义

Raft通过任期、选举、日志复制和多数派提交维护复制状态机。Commit 表示满足协议提交条件，Apply 表示状态机已执行该条日志。线性一致读取还需确认领导权与应用进度；日志/快照用于落后副本恢复。

16.2 租约与 Fencing Token

Lease（租约）限定拥有权期限，心跳用于续约；进程暂停后恢复可能继续发旧请求。Fencing Token（隔离令牌）用递增代号让资源端原子校验并拒绝旧拥有者。

协调方分配代号，提交端把校验与写入生效放在同一原子边界。要求“租约一过期立即禁写”时，还需及时安装新任期或实时检查租约状态；只记住已观察的最大代号，提供的是相应代际隔离。

16.3 两阶段提交与版本发布

2PC（两阶段提交）先让参与者 Prepare（准备），再由协调者决定 Commit/Abort，实现跨参与者原子提交；准备后等待最终决定可能阻塞。Raft 解决复制日志共识，两者可在系统中承担不同层次的职责。

Manifest 最后发布可实现特定对象组的原子可见性，前提是读者只从已提交清单进入。元数据成功与远端 Payload 的耐久性分别保证；竞争发布者、对象丢失和旧读者引用也纳入协议。

16.4 至少一次、幂等与外部副作用

At-least-once（至少一次投递）允许重复；Idempotency（幂等）让相同操作重复执行保持约定效果。请求 ID、参数摘要、结果和业务写入在同一事务边界内关联，才能把查重与效果绑定。

失败窗口处理
业务生效后，响应丢失用稳定幂等键重试或查询原结果
写去重记录后，业务还没执行就崩溃把状态转移与效果纳入同一原子边界
本地提交后，外部消息尚未发送Outbox（事务发件箱）持久记录待发事件
外部工具成功后，本地未记完成依赖下游幂等/查询，或对账与补偿

Exactly-once（恰好一次）应标明覆盖消息、状态变更还是外部效果。去重记录保留时间至少覆盖可能的重试窗口，相同键携带不同参数时按协议拒绝或识别冲突。

16.5 分片、滚动升级与验证

滚动升级按“兼容读取 → 新写入/迁移 → 清理旧格式”推进。Readiness（就绪）覆盖加载与必要依赖，旧请求持有其版本直至完成。回滚同时检查旧代码能否读取新数据。

17.3 距离、过滤与分布式 TopK

最大余弦、最大内积与最小平方 L2 给出相同排序

17.4 RAG 分块、证据与记忆

19.3 兑换题与多核任务调度

N 元买 N 瓶，2 空瓶换 1 瓶，每次兑换使空瓶数净减 1。N>0 且禁止借瓶时，最终留 1 空瓶，共喝 2N−1 瓶；允许借 1 瓶并归还时可达 2N，N=0 单独处理。

任务1…N，耗时分别为1…N，总工作W=N(N+1)/2
K个相同核、任务不可拆：完成时间下界 ≥ max(N, ceil(W/K))

固定 K 时关注最小完成时间；给定时间上限 T 时，核数至少 ceil(W/T)，且 T≥N。LPT（最长任务优先）把任务从长到短放入当前最空闲核，给出可行近似；严格最优需利用题目约束另行求解。

LPT：最小堆维护每核累计负载
# LPT 贪心近似：最小堆维护当前每核负载
import heapq
loads = [(0, i) for i in range(K)]
heapq.heapify(loads)
for duration in range(N,0,-1):
    used, i=heapq.heappop(loads)
    heapq.heappush(loads,(used+duration,i))
answer=max(x for x,i in loads)

19.4 LC 2712 与机器选择

LC 2712：对二进制串使用题设前缀/后缀翻转。相邻位在位置 i 不同，就需消除该边界，代价取 min(i,n−i)，累加所有变化边界。时间 O(n)、额外空间 O(1)。

最小翻转代价
def minimumCost(s):
    n=len(s)
    return sum(min(i,n-i) for i in range(1,n) if s[i]!=s[i-1])

最多选择 K 台机器，使 Σspeed×min(reliability) 最大：按 reliability 降序扫描，当前值作为最小可靠性候选；最小堆维护至多 K 个最大的 speed，累计和乘当前 reliability 更新答案。时间 O(n log n+n log K)，适用正速度与非负可靠性。

19.5 数字字符串插加号：所有表达式之和

题型固定为：相邻数字之间可插入或不插入加号，求所有方案的数值总和。扫描前缀时，维护表达式总和 total、最后一段总和 last、方案数 count。追加数字 d 会产生“拼接”和“新开一段”两种情况。

def sum_with_pluses(s: str) -> int:
    if not s or any(ch < '0' or ch > '9' for ch in s):
        raise ValueError("需要非空十进制数字串")
    total = last = int(s[0])
    count = 1
    for ch in s[1:]:
        d = int(ch)
        total, last = 2*total + 9*last + 2*count*d, 10*last + 2*count*d
        count *= 2
    return total
